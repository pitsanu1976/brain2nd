# ISO 14224

**หมายเหตุ: ไม่มีตัวมาตรฐาน ISO 14224 ใน raw sources** ส่วน "ความรู้ทั่วไป" ด้านล่างมาจากผู้เขียน wiki จึงยังเป็น `confidence: low` ส่วนเดียวที่มี source รองรับคือรายการรหัส failure mode ตามตัวอย่างใน RBMM (ดูหัวข้อ "หลักฐานรองจาก RBMM") ซึ่งอยู่ระดับ `medium` เฉพาะส่วนนั้น ระดับหน้ารวมยังคง low เพราะหนังสือเป็น secondary source ที่ยกตัวอย่าง ไม่ใช่ตัวมาตรฐาน (SPS/UST resolve แล้ว: UST หลัก, SPS = alias)

## ความรู้ทั่วไป (ยังไม่ได้ verify กับ source)

- ISO 14224 เป็นมาตรฐานสำหรับการเก็บและแลกเปลี่ยนข้อมูล reliability และ maintenance ของอุปกรณ์ในอุตสาหกรรม petroleum, petrochemical และ natural gas
- กำหนดโครงสร้างข้อมูล: equipment taxonomy (ลำดับชั้น), failure mode, failure mechanism, failure cause และ maintenance activity
- [[OREDA]] เป็นโครงการที่ใช้และสอดคล้องกับ taxonomy นี้

## หลักฐานรองจาก RBMM (p.132-134, Fig 5.14-5.17)

หนังสือ RBMM ยกตัวอย่าง ISO 14224 สำหรับ pump และ motor (RBMM p.132-134) และใช้กำหนด Failure Mode ระดับ Equipment รายละเอียดเต็มอยู่ใน [[Failure Data Recording]]

- **Boundary**: Fig 5.14 (pump: Starting System, Driver, Power Transmission, Pump Unit, Control and Monitoring, Lubrication System, Miscellaneous) และ Fig 5.16 (motor) เป็นตัวอย่างการตีกรอบ equipment ซึ่งสอดคล้องกับแนวคิด Sub Unit ใน [[Failure Hierarchy]] (การเทียบเป็นการตีความ)
- **รหัส failure mode ของ pump (Fig 5.15)**: 19 รหัส ตรงกับ [[Failure Mode]] ของ wiki **18 จาก 19** (FTS, STP, BRD, HIO, LOO, ERO, ELP, ELU, INL, VIB, NOI, OHE, PDE, AIR, STD, SER, OTH, UNK) ทั้งรหัสและชื่อ
- **รหัส failure mode ของ motor (Fig 5.17)**: 18 รหัส ไม่มี ELP และ INL แต่มี **OWD** (Operation without demand) ซึ่งไม่อยู่ใน 19 โหมดของ compressor ใน wiki
- ผลนี้ช่วยยืนยันว่ารายการรหัส 19 โหมดของ dataset ใกล้เคียงรายการใน ISO 14224 ที่หนังสืออ้าง จึงยกระดับความมั่นใจ **เฉพาะส่วนรายการรหัส failure mode** ได้ถึง medium (corroborated โดย source รองหนึ่งเล่ม) ส่วน failure mechanism, descriptor, resolution และ equipment taxonomy ของ compressor ยังไม่มีหลักฐานจากหนังสือ

## ความขัดแย้ง SPS vs UST (resolved)

**Resolved 2026-10-21 (ตัดสินโดยผู้ใช้):** ใช้ **UST** เป็นรหัสหลัก และถือ **SPS** เป็น alias (ข้อความด้านล่างเก็บไว้เป็นประวัติ)


- หนังสือ (Fig 5.15/5.17) ใช้รหัส **SPS** "Spurious stop" ส่วน dataset OREDA ของ wiki ใช้ **UST** "Spurious stop" ชื่อเดียวกัน รหัสต่างกัน
- ยังไม่มีตัวมาตรฐานมาตัดสินว่ารหัสใดถูก wiki เก็บทั้งสองมุมมอง ใช้ UST ต่อสำหรับข้อมูล compressor ([[UST Spurious Stop]]) และถือ SPS เป็น alias ที่ยังไม่ verify
- ตั้ง `contested: true` และบันทึกใน [[log]]

## การเชื่อมกับ wiki นี้ (การตีความ ไม่ใช่ข้อความใน source)

ลำดับชั้นใน [[Failure Hierarchy]] (Equipment -> Sub Unit -> Maintainable Item -> Failure Mode -> Failure Mechanism -> Failure Cause -> Resolution) สอดคล้องกับแนวคิดของ ISO 14224 ที่แยกข้อมูล equipment, failure และ maintenance แต่ **ชื่อรหัส 3-4 ตัวอักษรใน dataset นี้** (เช่น `PWTR`, `INST`, `FSIG`) เป็นรหัสของผู้จัดทำ dataset/OREDA ไม่ได้ยืนยันว่าตรงกับรหัสในมาตรฐานฉบับใด ดู [[CAUSE_CODE Convention]]
