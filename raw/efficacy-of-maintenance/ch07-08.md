## บทที่ 7 — Work Control System

### นิยามและตำแหน่งในระบบ (EOM p.112)
- ถ้า PM-Program คือ "หัวใจ" ระบบควบคุมงานคือ "สมอง" ที่สั่งการและรับรู้สถานะ
- Work Control = การกำหนดขั้นตอนวิธีปฏิบัติที่สัมพันธ์กับงานบำรุงรักษา + สื่อสาร/รายงานสถานะอย่างต่อเนื่อง

### หน่วยงานที่เกี่ยว (EOM p.112)
- โดยตรง: หน่วยผลิต, หน่วยพัสดุ-จัดซื้อ, HSE
- สนับสนุน: บัญชี-การเงิน, HR
- หลักการ: ออกแบบวิธีทำงานของแต่ละหน่วยแล้ว "สร้างความสัมพันธ์" ให้ข้อมูลไหลข้ามหน่วยได้ ไม่ใช่ต่างคนต่างมีระบบ

### ข้อมูลที่ใช้ร่วม (EOM p.113)
- กับหน่วยผลิต: ทะเบียนเครื่องทั้งหมด, ผลผลิตตามช่วงเวลา, การหยุดเนื่องจากเครื่อง, ตารางเดินเครื่อง/start-stop counter, ความสูญเสียวัตถุดิบ-เชื้อเพลิง-พลังงาน, Availability/Speed/Quality Loss (ฐานของ OEE)
- กับพัสดุ: ทะเบียนเครื่อง, รายการอะไหล่ตามกลุ่ม/ประเภท, รายการอะไหล่สำรองคลัง + stock level ที่บำรุงรักษากำหนด
- **คำแนะนำที่ขัดกับธรรมเนียมเก่า**: เลิกใช้รหัสตัวเลขยาว ๆ ใช้ชื่อย่อ/อักษรย่อ เพราะจำง่ายกว่าและส่งต่อไประบบบัญชีทรัพย์สินได้ (EOM p.113)

### 6 ขั้นของกระบวนการ (EOM p.114)
1. Work Initiation — เริ่มงาน (แจ้งซ่อม/plan/PM ครบกำหนด)
2. Work Assessment — ประเมินขอบเขตและสภาพ
3. Work Scheduling — กำหนดแผน/กำหนดการ
4. Work Execution — ปฏิบัติงาน
5. Work Closing and Reporting — ปิดงานและรายงาน
6. History Record — เก็บประวัติ

- การติดตามสถานะทั้ง 6 ขั้น = **Backlog Status Control** (ระบบควบคุมงานค้าง)
- Work Flow ของแต่ละโรงงานต่างกันได้ แต่หลักการเดียวกัน (EOM p.114)

### กิจกรรมเสริมให้ระบบมีประสิทธิผล (EOM p.124-126)
- Work permit/ความปลอดภัย, การจัดลำดับความสำคัญของงานค้าง, รายงานประจำ, การประชุมประจำวัน/สัปดาห์

## บทที่ 8 — Planned Outage

### Standard Planned Outage Package 3 แบบ (EOM p.131-132)
| แพ็คเกจ | ขอบเขต | ระยะหยุดโดยทั่วไป |
|---|---|---|
| Turnaround (Major Overhaul) | ครบทุกกิจกรรม + เครื่องหลักทุกตัว ละเอียดที่สุด | นานที่สุด (หลายสัปดาห์) |
| Semi-Turnaround (Overhaul) | Function Test, NDT, Calibration, Verification, Part Replacement บางตัว | 15-30 วัน |
| Minor Inspection (Yearly Inspection) | ตรวจสภาพเครื่องหลักเป็นหลัก งานอื่นเสริม | 7-15 วัน |

### 7 ขั้นของการบริหาร outage (EOM p.132)
Work Initiation → Outage Planning (scope) → Resources Preparation → Work Scheduling → Pre-Outage → Outage Execution → Post-Outage

- จุดสำคัญ: outage มีความซับซ้อนและปริมาณงานมาก จน **Work Control ธรรมดาไม่พอ ต้องใช้วิธีบริหารโครงการ (Project Management/CPM)** และซอฟต์แวร์จัดตาราง (EOM p.132)
- Scope มาจาก 4 แหล่ง: Backlog unplanned, Planned Outage Standard Package, Backlog PdM, งาน IM (รูปที่ 8.5, EOM p.133)
- Pre-Outage: เตรียมคน (รวมจ้างเหมา) อะไหล่ เครื่องมือ พื้นที่ และ permit (EOM p.140)
- Outage Execution: ควบคุมตามแผน ตรวจงานค้างรายวัน แก้ปัญหาหน้างาน (EOM p.141-144)
- Commissioning: Pre-Start-up (ตรวจระบบย่อยก่อนเดิน) + Start-up (เดินจริง) — แยกจาก "ซ่อมเสร็จ" (EOM p.145-146)
- บทสรุป (EOM p.147-148): ตัวชี้วัด outage คือ ตรงเวลา (schedule), ตรงขอบเขต (scope), ไม่มีงานค้างหลังกลับมาเดิน, และไม่เกิด unplanned shutdown ตามมา

## ข้อสังเกต

- การแยก "Pre-Start-up" กับ "Start-up" และ "Post-Outage" คือสิ่งที่ระบบ CMMS ทั่วไปมักไม่มี — เป็นช่องที่ต้องใช้ checklist นอกระบบ
- ระยะ 7-15 / 15-30 วันเป็นค่าประสบการณ์ของผู้เขียน (โรงไฟฟ้า/โรงงานขนาดใหญ่) ไม่ควรใช้เป็น benchmark ตรง ๆ กับโรงงานอื่น
