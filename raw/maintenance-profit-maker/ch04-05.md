# บทที่ 4 ระบบบริหารงานบำรุงรักษา (Maintenance Management System)

Source: book p.59-81 (PDF p58-80)

## นิยาม MMS (MPM p.60)
- ระบบบริหารงานบำรุงรักษา = การจัดกิจกรรมซ่อมแซม/บำรุงรักษาทั้งหมดให้เป็นกระบวนการต่อเนื่อง เพื่อให้เครื่องจักรในความรับผิดชอบได้ผลผลิตสูงสุดตลอดอายุ ด้วยค่าใช้จ่ายต่ำสุด
- การบริหารงานบำรุงรักษา = จัดการงานทั้ง 16 งานให้อยู่ภายใต้ MMS ระบบที่ดีใช้ได้ทั้งแบบมีหรือไม่มีคอมพิวเตอร์ (CMMS)

## กิจกรรมบำรุงรักษา 4 กลุ่ม 16 งาน (รูปที่ 4.1, MPM p.60)
แกนตั้ง = ความวิกฤต/ความสำคัญ (H บน, L ล่าง); แกนนอน = วงจรชีวิตของงาน จาก Discrete (ซ้าย) ไป Continuous (ขวา) ทั้งหมดวางบนฐาน "Maintenance Management System"

| กลุ่ม | งาน 4 อย่าง |
|---|---|
| Fault Recovery (เสีย-ซ่อมให้กลับไปใช้งานได้) | Trouble Shooting, Component Change, Component Rebuilt, Spare Parts |
| Preventive-Proactive (ป้องกัน-เชิงรุก) | Predictive, Condition Monitoring, Preventive Maintenance, Turnaround |
| Modification Project (โครงการปรับปรุง/เปลี่ยนใหม่) | Project Management, Commissioning, Installation, Engineering |
| Maintenance Engineering (วิศวกรรมบำรุงรักษา) | Plant/Maintenance Audits, Maintenance Management Improvement, Reliability Improvement, Plant/Equipment Performance Improvement |

(การจัดกลุ่มเป็นคอลัมน์อ่านจากตาราง OCR ของรูป ตรงกับ RBMM Fig 1.3)

## ระบบบริหารงานบำรุงรักษาที่ดีต้องมี 9 ข้อ (MPM p.60-61)
1. ขึ้นทะเบียนเครื่องจักรทั้งหมดในความรับผิดชอบ พร้อมข้อมูลเทคนิค การเงิน และการบริหารประจำตัวเครื่อง
2. จัดหมวดเครื่องจักรตามความสำคัญต่อการผลิต (Criticality Classification) เพื่อกำหนดชนิดงานและลำดับก่อนหลัง
3. ติดตามงานทั้ง 16 ประเภทได้ตั้งแต่ต้นจนจบเป็นขั้นตอน เก็บประวัติครบ ประสานงานและใช้ทรัพยากรได้มีประสิทธิภาพ
4. ตอบสนองข้อกำหนดด้านสิ่งแวดล้อม
5. รวมการบริหารความปลอดภัยทั้งคนและทรัพย์สิน
6. บันทึกค่าใช้จ่ายด้วยระบบบัญชีที่ถูกต้อง โดยเฉพาะการตั้งและใช้งบประมาณ
7. ทำงานสอดคล้องกับระบบอื่นของบริษัท (ผลิต, บัญชี/การเงิน, บุคคล, คลังอะไหล่) โดย **ไม่บันทึกซ้ำ (No Double Entry)**
8. บันทึกข้อมูลเทคนิคที่จำเป็น เพื่อใช้ร่วมกับข้อมูลการเงินทำแผนยุทธศาสตร์
9. ให้รายงานเชิงวิเคราะห์ทั้งทางเทคนิคและเศรษฐศาสตร์

## 6 ขั้นของกระบวนการ (MPM p.61)
1. Work Requests (แจ้งซ่อม/รับรู้ความเสียหาย)
2. Work Order Initiation and Planning (วางแผน)
3. Work Order Scheduling (จัดการดำเนินงาน/กำหนดวัน) — ข้อความในรายการ p.61 พิมพ์ชื่ออังกฤษเป็น "Execution and Control" ซ้ำกับข้อ 4 แต่หัวข้อในบท (p.69) ใช้ "Work Order Scheduling"
4. Work Order Execution and Control (ปฏิบัติงาน)
5. Work Completion and Close to History (ปิดงานลงประวัติ)
6. Maintenance Work Analysis (วิเคราะห์งาน)

## ผังกระบวนการตัวอย่าง (รูปที่ 4.2, MPM p.62)
5 แถบ: Initiation -> Planning -> Scheduling -> Execution -> Close (อ่านจากรูป)
- Initiation: ฝ่ายผลิตเปิดและอนุมัติ WR; Predictive maintenance ใช้ปรับเงื่อนไข PM; PM เกิดตามเวลา/คาบ/เงื่อนไข
- Planning: ตรวจ WR กับ Equipment Register -> เปิด WO หรือแจ้งยกเลิกกลับฝ่ายผลิต -> Planning & Estimates (อะไหล่ แรงงาน เครื่องมือ วิธีการ งานมาตรฐาน) -> อนุมัติ
- Scheduling: กำหนดวันตามแผนผลิต จองอะไหล่
- Execution: ขออนุญาต/รับเครื่อง พิมพ์ WO ซ่อม เบิก/คืนผ่านคลังและจัดซื้อ -> คืนเครื่อง ฝ่ายผลิตตรวจรับ
- Close: บันทึกอะไหล่ ชั่วโมง แรงงาน ค่าใช้จ่าย ค่าวัด แบบ ส่งบัญชี/บุคคล -> ตรวจสมบูรณ์ -> ลงประวัติ -> วิเคราะห์
- มีจุด "อนุมัติ?" อย่างน้อย 3 จุด และจุด "งานเสร็จ?" / "เสร็จสมบูรณ์?" 2 จุด

## ขั้นที่ 1: การเกิดงาน (Work Requests) (MPM p.63-67)
- ผู้ใช้เครื่อง/ฝ่ายผลิตพบอาการผิดปกติ -> ออกใบแจ้งซ่อม (WR) บันทึกตามที่พบ (as found) ต้องกลั่นกรอง หรือเร่งรัดถ้าด่วน; ใน CMMS แจ้งผ่านหน้าจอ (MPM p.63)
- ขั้นกลั่นกรองเบื้องต้นลดปริมาณงาน: ประเมินความเร่งด่วน หรือยกเลิกโดยไม่เข้าระบบส่วนที่เหลือ (MPM p.63)
- ใบแจ้งซ่อมตัวอย่าง (รูปที่ 4.4, MPM p.64): เลข WR, วันเวลา, เครื่อง/อุปกรณ์, ผู้แจ้งและหน่วยงาน, อาการ, ความเร่งด่วน (NOR = ปกติ), วันที่ต้องการ, อนุมัติ 2 ชั้น (Owner Approve + Maintenance Approve), WO ที่ผูก (WO Type = CM, Cost Center, Status)
- รายงานหลัก:
  1. **Work Request Backlogs** WR ที่ยังไม่ได้ตอบสนอง เพื่อเร่งรัดหรือยกเลิก (รูปที่ 4.5) (MPM p.63-64)
  2. วิเคราะห์เชิงปริมาณการเกิดปัญหาและสภาพที่พบ; ส่ง WR ทางอินเทอร์เน็ตได้; CMMS เชื่อม Plant Control and Information System ให้ระบบควบคุมแจ้งความผิดปกติเข้า CMMS ได้ (MPM p.64-65)
- รายงานสรุปจำนวนงานแจ้งซ่อม (รูปที่ 4.6, MPM p.65): คอลัมน์ งานยกมา / เข้า / เสร็จ / ยกเลิก / ยกไป ตามหน่วยงานซ่อม; ตัวอย่างหน่วยงาน 104 เข้า 65 เสร็จ 64 ยกไป 1; หน่วยงาน 105 เข้า 120 เสร็จ 120 (ผลรวมถูก; derived)

### งานที่ไม่ผ่านใบแจ้งซ่อม (MPM p.65-67)
- **PM และ Condition Monitoring** ตามกำหนด: เกิดเมื่อครบเงื่อนไข เช่น ตามวันปฏิทิน (calendar days), ชั่วโมงใช้งาน/มิเตอร์, หรืองานซ่อมใหญ่ (Turnaround/Shutdown) ไม่ต้องผ่าน WR เพราะเครื่องยังไม่เสีย เป็นงานที่บำรุงรักษาเข้าหาเครื่องเอง ระบบออก WO ให้อัตโนมัติ เงื่อนไขต้องปรับให้ตรงสภาพปัจจุบันเสมอ (MPM p.65)
- **Predictive Maintenance** ใช้ความรู้วิศวกรรมวิเคราะห์สาเหตุเสีย ทำแบบจำลองความน่าเชื่อถือ/อายุ เพื่อกำหนดคาบและเงื่อนไขของ PM (MPM p.65)
- ตัวอย่างรายงาน: PM ที่ถึงกำหนดรายเครื่อง (รูปที่ 4.7) และแผน PM รายเดือนแบบปฏิทินทำเครื่องหมาย X (รูปที่ 4.8, มี.ค. 2003) (MPM p.66)
- **Modification Projects, Plant/Equipment Performance Improvement, Reliability Improvement** เกิดจากความต้องการปรับปรุงเครื่องเพื่อเพิ่มสมรรถนะหรือแก้ปัญหาสะสมที่คุมไม่ได้/ไม่คุ้มทางเศรษฐศาสตร์ แต่ต้อง execute ผ่าน MMS เพื่อให้ข้อมูลเทคนิคและการจัดการต่อเนื่อง และเก็บประวัติการเปลี่ยนแปลงเครื่องครบ (MPM p.67)
- **งานเร่งด่วน**: ลงมือได้ทันที ทำเอกสารคู่ขนาน เช่น แจ้งซ่อม เปิด WO จัดหาปัจจัยด้วยวาจาก่อน แล้วตามด้วยเอกสารที่มีเลขอ้างอิง (MPM p.67)
- **เลขอ้างอิงหลัก** = เลขใบแจ้งซ่อม และเลขใบสั่งซ่อม ใช้ผูกกับระบบอื่น เช่น ใบเบิกของ การรวบรวมค่าแรง การจ้างเหมา (MPM p.67)

## ขั้นที่ 2: งานวางแผน (Work Order Initiation and Planning) (MPM p.67-69)
- บำรุงรักษากรอง WR อีกรอบ (ทางการหรือไม่ก็ได้ เช่น ตรวจกับผู้แจ้ง) เป้าหมาย = บันทึกอาการเสียให้ถูก เพื่อให้ประวัติอาการและวิธีแก้ใช้อ้างอิงได้ในอนาคต (MPM p.67)
- ทางเลือก: เปิด WO หรือตกลงกับผู้แจ้งว่าแก้ได้โดยไม่ต้องเปิด WO (ไม่กระทบประวัติเครื่อง) WR ที่ยกเลิกยังเก็บในแฟ้มยกเลิก (MPM p.67)
- WO ที่เปิดแล้วต้องเข้ากลุ่ม **Backlogs** ทันที ระบบต้องแยกงานตามสถานะได้

### สถานะหลักของ WO 7 สถานะ (MPM p.67-68)
| # | สถานะ |
|---|---|
| 1 | Initiated (เริ่มต้น) |
| 2 | Planned (ประเมินการ) |
| 3 | Scheduled (จัดวันทำงาน) |
| 4 | Wait (รอ) |
| 5 | Issued (พิมพ์ใบสั่งงานแล้ว) |
| 6 | Finished (งานเสร็จ) |
| 7 | Complete (เสร็จ เก็บข้อมูลครบ พร้อมปิดลงประวัติ) |

หมายเหตุ: ตัวอย่างรายงานในบทใช้รหัสสถานะตัวเลขของซอฟต์แวร์ เช่น WR "10 Work Initiated", "70 Approve WR" (รูปที่ 4.5) และ WO "30 Scheduled", "50 In Program" (รูปที่ 4.14) ซึ่งเป็นรหัสของโปรแกรมตัวอย่าง ไม่ใช่เลข 1-7 ข้างบน

### คำถามของการวางแผน 7 ข้อ (MPM p.68-69)
1. ต้องใช้ทรัพยากรอะไร ผู้เชี่ยวชาญ วิศวกร ช่าง แรงงานอย่างละเท่าไร ค่าใช้จ่ายเท่าไร ต้องจ้างเหมาหรือไม่ จากใคร
2. วิธีทำ มีงานมาตรฐานอ้างอิงหรือไม่ แบบและข้อมูลเทคนิค
3. ขั้นตอนควบคุม การตัดแยกระบบด้านความปลอดภัย สิ่งแวดล้อม และเอกสารกำกับ
4. ใช้เวลากี่ชั่วโมง
5. ใช้เครื่องมือและอะไหล่อะไร อ้างอิงจากระบบคลังได้หรือไม่ ถ้าไม่มีต้องสร้างรหัสหรือซื้อตรง
6. ค่าใช้จ่ายรวมทั้งสิ้น
7. ใช้งบหน่วยงานใด ใครอนุมัติ
- ผลที่ได้ = ขนาดงานและระยะเวลา ข้อมูลต้องเป็นปัจจุบันเพราะมีผลต่อ scheduling
- รายงานหลักของงานวางแผน: (1) WO ระหว่างวางแผน (Backlogs) (2) ค่าใช้จ่ายประเมินของแต่ละงาน (3) รายการรออนุมัติ (4) รายละเอียดสาเหตุต่าง ๆ (MPM p.69)

## ขั้นที่ 3: กำหนดวันดำเนินงาน (Work Order Scheduling) (MPM p.69-70)
- เงื่อนไขหลัก 2 ข้อ: (1) เครื่องพร้อมให้ซ่อม ยึด Production Plan หรือการตกลงหยุดเครื่องทั้งหมด/บางส่วน (2) ทรัพยากรตามแผนพร้อมในวันทำงาน (MPM p.69)
- อุปสรรคใหญ่ที่สุดคือ **ความพร้อมของอะไหล่** ซึ่งจองไว้ให้งานได้; ถ้ากำหนดวันไม่ได้ให้ย้ายงานเข้าแฟ้ม **รอ (Wait)** แยกหมวดตามสาเหตุเพื่อติดตามเร่งรัด (MPM p.69)
- ใช้ **ประชุมประจำวันสั้น ๆ** ระหว่างหน่วยงานที่เกี่ยวข้อง ตรวจความพร้อมของงานวันพรุ่งนี้และสัปดาห์หน้า งานของวันนี้คืองานที่ตกลงไว้เมื่อวาน; ถ้าระบบนิ่ง ตกลงล่วงหน้าเป็นสัปดาห์หรือเดือนได้ (ไม่มีงานด่วนตื่นเต้น) ตารางต้องทบทวนตามความพร้อมของปัจจัยตลอดเวลา (MPM p.69)
- CMMS มี **Resource Leveling Function** เลื่อน/ปรับตารางให้ตรงข้อจำกัดของทรัพยากร แต่จัดอัตโนมัติไม่ง่าย โดยเฉพาะกำลังคนที่ลาโดยไม่คาดหมาย การเปลี่ยนตารางกระชั้นชิดด้วยโปรแกรมทุกครั้งอาจไม่สะดวก (MPM p.69-70)
- รายงานหลัก (MPM p.70): (1) ผังแผนการผลิตที่แสดงช่วงที่เครื่องว่างให้ซ่อม (2) งานในแฟ้มรอ แยกหมวด:
  - รออะไหล่
  - รอกำลังคน
  - รอเครื่องมือ
  - รอเครื่องจักรหยุด
  - อื่น ๆ

## ขั้นที่ 4: ปฏิบัติงาน (Work Order Execution and Control) (MPM p.70-73)
- เมื่อได้วันเริ่ม ให้เตรียมเอกสารเป็นชุด:
  1. เตรียมความพร้อมหน้างานตามเวลา (logistics) เบิกอะไหล่ เครื่องมือ
  2. โอนเครื่องมาอยู่ในความรับผิดชอบของบำรุงรักษา (**Released for Maintenance**)
  3. ขั้นตอนความปลอดภัย: แขวนป้าย (**Safety Tags procedures**) และตัดแยกอุปกรณ์ (isolation) (MPM p.70-71)
- รายงานติดตามงาน (MPM p.71):
  1. งานระหว่างทำ พร้อม check list ความก้าวหน้า ข้อมูลเทคนิคและค่าใช้จ่ายที่เกิด เพื่อสรุปเมื่อจบ รวม check list ความปลอดภัย
  2. งานที่ติดอุปสรรคต้องรอ พร้อมรายละเอียดเพื่อเร่งรัด
  3. งานจ้างเหมาภายนอก ควรอยู่ในระบบเดียวกัน เพื่อประเมินผู้รับเหมาและเตรียมค่าใช้จ่าย
- เอกสารต้องเสร็จพร้อมงานในเวลาที่สมควร
- ขั้นตอนสำคัญเมื่องานเสร็จ (MPM p.71-72):
  1. ปลดป้าย (Safety Tags) และต่อเครื่องกลับเข้าใช้งาน
  2. คืนเครื่องให้ฝ่ายผลิต ฝ่ายผลิตเป็นผู้ตรวจรับ (**Accepted for Production**)
  3. รวบรวมรายละเอียดทั้งหมดลงประวัติ โดยเฉพาะค่าใช้จ่าย
- ด้านเทคนิคต้องบันทึกค่าวัดให้ครบ และปรับแบบให้เป็นปัจจุบัน (MPM p.73)

## ขั้นที่ 5: ปิดงานลงประวัติ (Work Completion and Close to History) (MPM p.73-74)
- ฝ่ายผลิตรับเครื่องกลับ = การซ่อมเสร็จ แต่ **WO ยังไม่ปิด** จนกว่าย้ายข้อมูลครบถ้วนเข้าแฟ้มประวัติประจำเครื่อง (MPM p.74)
- ต้องมีระเบียบว่าข้อมูลประวัติห้ามแก้โดยไม่ได้รับอนุญาต เพราะ MMS ต้องกระทบยอดกับระบบอื่นตลอด ข้อมูลเกิดที่ระบบเดียวเท่านั้น (**Single Entry**) การแก้ข้อมูลเพียงจุดเดียวอาจทำให้ข้อมูลที่เกี่ยวข้องเสียหายและข้อมูลทั้งบริษัทไม่น่าเชื่อถือ โดยเฉพาะการเงิน
  - ตัวอย่าง: แก้จำนวนอะไหล่ที่ใช้โดยพลการ โดยไม่แก้ที่ต้นทาง (ใบเบิกคลัง) ทำให้ค่าใช้จ่ายไม่ตรงงบการเงิน และกระทบยอดคงคลังไม่ได้ถ้าปิดงวดบัญชีแล้ว
- จึงต้องทบทวนเอกสารอ้างอิงให้ครบก่อนปิด; CMMS ออกแบบมาป้องกันอยู่แล้ว การแก้งานที่ปิดแล้วต้องมีขั้นตอนถูกต้องและทำโดยผู้มีอำนาจเท่านั้น
- ข้อมูลเทคนิคที่ไม่ครบหรือไม่กลั่นกรอง -> วิเคราะห์ผิด -> ปรับกลยุทธ์ผิด
- ข้อมูลสำคัญในการสรุปปิดงาน 3 อย่าง: (1) สาเหตุการเสียตามหลักวิศวกรรม (2) ข้อมูลเวลา (3) ข้อมูลการใช้ปัจจัย (MPM p.74)

## ขั้นที่ 6: วิเคราะห์งานบำรุงรักษา (Maintenance Work Analysis) (MPM p.74-77)
จุดเริ่มต้นของการปรับปรุงทั้งหมด ครอบคลุม 9 เรื่อง:
1. วิเคราะห์สาเหตุการชำรุด (Failure Mode Cause and Effect Analysis, Root Cause Analysis) จัดสาเหตุเป็นเครือข่ายต้นไม้ (Failure Tree) (MPM p.74)
2. หาจุดสมดุลของ Predictive Maintenance, Condition Monitoring, PM และความถี่ที่ดีที่สุดในการวัด/เข้าทำ PM ด้วย Reliability Engineering; มีโปรแกรมช่วยหา PM หรือ CBM ที่เหมาะสม (CBM Optimize) แต่ต้องมีข้อมูลซ่อมย้อนหลังพอสมควร (MPM p.75)
3. รายงานค่าใช้จ่ายตามหน่วยงาน (MPM p.75)
4. ดัชนีพื้นฐาน MTBF, MTTR, MWT (Mean Wait Time) (MPM p.75)
5. ทบทวนค่าใช้จ่าย 10 หรือ 20 อันดับแรก (MPM p.75)
6. ทบทวนปัญหา 10 หรือ 20 อันดับแรก (MPM p.75)
7. OEE ที่มีผลจากงานบำรุงรักษา ทั้งโรงงานและรายอุปกรณ์ แยกความสูญเสียหลัก: Availability Losses, Performance/Speed Losses, Quality Losses (MPM p.75)
8. ค่าใช้จ่ายอะไหล่ เพื่อปรับปริมาณสำรองและรายการที่ต้องสำรอง (MPM p.77)
9. การตั้งและใช้งบประมาณ (MPM p.77)
- ผลวิเคราะห์ทำเป็นดัชนีชี้วัดได้ (รายละเอียดบทหลัง); ระบบอะไหล่เป็นปัจจัยสำคัญต่อความสำเร็จของการซ่อม แยกเป็นบทถัดไป (MPM p.77)

## สรุปบทที่ 4 (MPM p.81)
- MMS จำเป็นเช่นเดียวกับระบบบัญชี บุคคล การผลิต การตลาด หลักการในบทเป็นระบบมาตรฐานที่ใช้ได้จริง ปรับบางขั้นตามระบบอื่นของแต่ละบริษัท

# บทที่ 5 การจัดการวัสดุอะไหล่ (Spare Part Management)

Source: book p.83-90 (PDF p81-88)

## ความสำคัญของต้นทุนอะไหล่ (MPM p.84)
- ค่าอะไหล่เป็นสัดส่วนสูงมากของค่าซ่อมบำรุง บางครั้งมากกว่ากำไรประจำปี
- **ประเทศอุตสาหกรรมเก็บสำรองอะไหล่เฉลี่ยราว 3-5% ของราคาเครื่องจักร** และ **ค่าใช้จ่ายในการเก็บสำรองราว 20%-40% ของมูลค่าอะไหล่ที่เก็บ** (หนังสือไม่ระบุว่าต่อปี แต่บริบทคือค่าเก็บรายปี) เหตุผลที่ลงทุน = ประกันความสามารถในการผลิต
- องค์กรส่วนน้อยได้ผลคุ้ม เพราะปัญหา: อุปกรณ์หลากหลาย อะไหล่เดียวกันถูกตั้งรหัส/ชื่อต่างกัน, อัตราใช้ไม่คงที่, lead time ไม่แน่นอน
- ต้นทุนอะไหล่มี 2 ด้าน: ต้นทุนการมีและเก็บ + ต้นทุนการขาด (ความเสียหายเมื่อไม่มีของตอนต้องใช้)
- ในไทยอะไหล่ส่วนใหญ่นำเข้า lead time นาน จึงต้องเก็บมาก ความรู้การบริหารลดค่าใช้จ่ายนี้ได้มาก
- การบริหารอะไหล่ต้องใช้ความรู้เทคนิค (สถิติ การวิเคราะห์) มากกว่าการจัดการ เป็นส่วนหนึ่งของ Industrial Engineering บทนี้ให้เฉพาะแนวคิด ส่วนการปรับปรุงอยู่ในบทที่ 11; สาระคือการปรับปรุงต่อเนื่อง

## เป้าหมาย 4 ข้อ (MPM p.84)
1. Stock Level ต่ำที่สุด
2. Stock Availability / Service Level สูงที่สุด
3. Stock Turn Over สูงที่สุด
4. โดยที่ Plant Availability สูงที่สุด

## กลยุทธ์สำหรับโรงงานใหม่ (MPM p.84-86)
### 1. Stock Level ต่ำสุด (MPM p.84-85)
- เครื่องใหม่ยังไม่มีประวัติ ใช้ข้อมูลโรงงานที่มีเครื่องคล้ายกัน หรือคำแนะนำผู้ผลิตเป็นแนวทาง แต่ต้องสอบทานกับดัชนีอุตสาหกรรมเดียวกัน เช่น อะไหล่คงคลัง 3-5% ของราคาเครื่องจักร
- % รวมไม่ใช่ประเด็นหลัก ที่สำคัญคือ **การกระจายของอะไหล่** การจัดที่มีประสิทธิผล = วิเคราะห์ความวิกฤตของเครื่อง/สายการผลิตก่อน แล้วจัดปริมาณให้เหมาะ

### บทบาทของอะไหล่ตามความวิกฤต (รูปที่ 5.1, MPM p.85)
| กลุ่มเครื่อง | สัดส่วน | กลยุทธ์ |
|---|---|---|
| วิกฤตสูงสุด | ~20% แรก | สนับสนุนด้วยอะไหล่เกือบ 100% + กิจกรรมอื่น (Inspection/RBI, RCM/FMEA) |
| วิกฤตปานกลาง | ~50% | ซ่อมเชิงรุก เน้นการเข้าดูแล วิเคราะห์ ทำนายการเสียด้วย Reliability Engineering มากกว่าการสะสมอะไหล่ |
| วิกฤตต่ำ | ~30% | ไม่ต้องสะสมมาก ใช้การจัดหาเมื่อต้องการหรือจ้างเหมาภายนอก (บางเครื่องให้ OEM) ซ่อมเชิงรับ (CM Module) |

ส่วนประกอบในผัง (อ่านจากรูป): Asset Management -> Asset Register Module -> วิเคราะห์ความวิกฤต (FCA Module) -> จัดอันดับคะแนนวิกฤต ทำสม่ำเสมอให้เป็นปัจจุบัน; แยกตามความแน่นอนของอายุใช้งาน/เงื่อนไข: เงื่อนไขชัด -> ซ่อมตามเงื่อนไข, อายุแน่นอน -> กำหนดการซ่อมคงที่/เปลี่ยนถ่าย; ทุกทางเชื่อมกับโปรแกรมบริหารอะไหล่ ข้อมูลพยากรณ์ และนำไปสู่ Improved Reliability / Availability / Maintainability

### 2. Service Level สูงสุด (MPM p.86)
```
ระดับการให้บริการ (Service Level / Stock Availability)
  = จำนวนรายการที่เบิกได้ครบจากคลัง / จำนวนรายการทั้งหมดที่เบิกจากคลัง
```
- ดัชนีสำคัญมากแต่ใช้คุมน้อยเกินไป ต้องแก้ที่ขั้นตอนเบิกจ่ายและคืนของ; โรงงานใหม่ต้องใช้ MMS ให้ได้ผล แล้วใช้ดัชนีเป็น feedback กำกับการปฏิบัติ

### 3-4. Stock Turnover และ Plant Availability สูงสุด (MPM p.86)
- โรงงานใหม่ต้องคุมระบบซ่อมและการเบิกอะไหล่ให้เคร่งครัด ไม่เช่นนั้นวัดดัชนีทั้งสองไม่ได้; ปัญหาอยู่ที่การอบรมพนักงานและรายงานสม่ำเสมอ ต้องทำตั้งแต่เริ่ม

## การบริหารอะไหล่เชิงคุณภาพและเชิงปริมาณ (โรงงานที่เดินเครื่องเข้าที่แล้ว) (MPM p.86-87)
- หลังทดลองเดินและปรับแต่ง อาจพบคอขวดที่ต้องดูแลเครื่องและสำรองอะไหล่พิเศษ ช่วงนี้ควรวิเคราะห์ความวิกฤตและปรับกลยุทธ์ต่อเนื่อง คะแนนวิกฤตจะเปลี่ยนเข้าใกล้ความจริงขึ้น
- เป้าหมาย 4 ข้อเหมือนเดิมแต่สัมพันธ์กันมากขึ้น กิจกรรมประจำ = วิเคราะห์ความวิกฤตรายเครื่อง, **ABC analysis**, และ **การวิเคราะห์ราคาและการเคลื่อนไหว**
- แบ่งอะไหล่เป็นกลุ่ม (MPM p.87):
  - **หมุนเร็ว** -> optimise ด้วย **Quantitative Inventory Management** เช่น ABC เพราะปริมาณหมุนเวียนสูงพอจะกลบปัจจัยอื่น ใช้ข้อมูลการใช้เป็นหลัก
  - **ที่เหลือ (80%)** เป็นต้นเหตุสะสมเกิน/ขาด และค่าใช้จ่ายสูง -> ใช้ **Qualitative Inventory Management** วิเคราะห์ราคาและความวิกฤตของเครื่อง เพราะใช้ไม่บ่อย ไม่มีประวัติพอ หรือข้อมูลไม่ถูกต้อง
  - ใน 80% นั้น มี **Insurance Items** (ต้องมีตามเงื่อนไขประกัน) 20% -> เหลือ **60%** ที่ต้อง optimise (ตัวเลข 20% ของกลุ่มหมุนเร็วเป็นนัยของข้อความ ไม่ได้พิมพ์ตรง)

## การวิเคราะห์ ABC (MPM p.87)
แบ่งจาก "ปริมาณการใช้" ทั้งปี:

| กลุ่ม | สัดส่วนปริมาณการใช้ทั้งปี | สัดส่วนจำนวนรายการ |
|---|---|---|
| A | 70% | 10% |
| B | 20% | 20% |
| C | 10% | 70% |

- ABC แยกของใช้มาก/ปานกลาง/น้อย เพื่อบริหารปริมาณโดยรวม แต่ **ไม่ครอบคลุมราคาและความวิกฤตรายรายการ** จึงต้องดูเป็นรายรายการว่าเกิดอาการเหล่านี้หรือไม่:
  - สะสมมากไป / น้อยไป
  - สั่งเร็วไป / ช้าไป
  - ต้องสั่งมากกว่าเดิม / น้อยกว่าเดิม
  - อัตราหมุนเวียนดี / ไม่ดีต้องปรับปรุง

## การวิเคราะห์เชิงราคาและการเคลื่อนไหว (MPM p.88-89)
จัดอะไหล่ตามกระแสหมุนเวียน (Movement) x ราคาต่อหน่วย (Cost):

| Movement \ Cost | High | Medium | Low |
|---|---|---|---|
| Fast | FH | FM | FL |
| Medium | MH | MM | ML |
| Slow | SH | SM | SL |

จับคู่ 9 ช่องเข้า 4 โมเดล:

| กลุ่ม | โมเดล | ใช้กับ | วิธีจัดการ |
|---|---|---|---|
| FH, FM, MH | **Perpetual Inventory Model (PIM)** | เคลื่อนไหวเร็ว-ปานกลาง ราคาสูง-ปานกลาง | สั่งด้วย EOQ เพื่อสมดุลค่าจัดหาและค่าครอบครอง |
| FL, MM | **Minimum-Maximum Model (MMM)** | เคลื่อนไหวเร็ว-ปานกลาง ราคาปานกลางลงต่ำ | เติมให้พอตลอด จัดหาแบบ **Blanket Order** (ซื้อเป็นก้อนล่วงหน้า) คงคลังวิ่งระหว่าง Max-Min |
| ML, SM, SL | **Two Bin System (TBS)** | เคลื่อนไหวปานกลาง-ช้า ราคาปานกลาง-ต่ำ | แบ่ง 2 ที่เก็บ (ชั้นบน/ชั้นล่าง) เบิกชั้นบนก่อน พร่องถึงชั้นล่างจึงสั่งเติม |
| SH | **Issue Replacement Model (IRM)** | ราคาสูง เคลื่อนไหวช้า | ปริมาณเก็บขึ้นกับ Criticality และจำนวนที่ติดตั้งในเครื่อง; สั่งเท่าจำนวนที่ใช้ไป |

### สูตร EOQ ของ MPM (MPM p.88)
```
EOQ = sqrt( 2 x A x B / (C x D) )
A = ค่าใช้จ่ายในการจัดซื้อต่อหนึ่งรายการ (ordering cost ต่อครั้ง)
B = อัตราการเบิกใช้ต่อปี
C = ราคาต่อชิ้น
D = ค่าครอบครองเป็นเศษส่วนของราคาต่อหน่วย (ต่อปี)
```
- ตัวอย่างตัวเลข: หนังสือไม่ให้ worked example
- เทียบ (derived): เทียบเท่า sqrt(2 x A x CO / (C x I)) ของ SPO โดย MPM-A = SPO-CO, MPM-B = SPO-A, MPM-D = SPO-I; และ C x D = Ch ของ RBMM

## Spare Part Optimization (โรงงานที่ผลิตมานาน) (MPM p.89-90)
- ต้องประเมินสภาพปัจจุบันก่อน ข้อมูลการใช้อะไหล่และประวัติซ่อมจำเป็นต่อการเห็นสถานการณ์และกำหนดแผน
- **Spare Part Inventory Management Performance Analysis/Audit**: สำรวจสภาพปัจจุบัน ประเมินประสิทธิผลและการจัดการอะไหล่ อาจขยายถึงประสิทธิผล/คุณภาพงานบำรุงรักษา โดยหา OEE แล้วโยงไปคุณภาพการบำรุงรักษาและการจัดการอะไหล่; ได้ภาพรวมและ **SWOT Analysis**; ผลสำคัญคือข้อแนะนำ ต้องทำโดยผู้มีประสบการณ์ที่เชื่อถือได้ บริษัทที่ปรึกษาเป็นทางเลือก (MPM p.89)
- กลยุทธ์ปรับปรุงจากผลประเมิน 5 ข้อ (MPM p.89-90):
  1. **ปรับปรุงการใช้**: PM พยากรณ์ความต้องการอะไหล่ล่วงหน้าได้ จัดหาเมื่อต้องการ ไม่ต้องตุนนาน ยิ่งพยากรณ์ได้มาก ยิ่งลดเงินลงทุนสำรองได้มาก แต่ต้องมี MMS ที่ดี
  2. **ปรับปรุงการเก็บสำรอง**: ประวัติการเบิกที่ดี รวมรายการที่ขาด/จ่ายไม่ได้ เป็นข้อมูลปรับระดับสำรอง ตัวอย่างองค์กร **ลดยอดสำรองได้ 16%** เพียงทบทวนประวัติเบิกแล้วปรับระดับ
  3. **ปรับปรุงการจัดหา**: lead time ไม่แน่นอนทำให้ต้องเก็บมาก แก้ร่วมกับผู้ขาย หรือใช้ **Consignment Stock** (ผู้ผลิตเก็บอะไหล่ไว้ที่เรา จ่ายเงินเมื่อเบิกใช้)
  4. **การวัดสมรรถนะ**: มีระบบวัดที่โยงกับการเพิ่มผลผลิต รายงานผู้บริหารรายเดือน
  5. **วัดและประเมินผล**: วางแผนตั้งแต่ต้น ทั้งดัชนี ข้อมูลที่ต้องใช้ และวิธีวัดที่สะท้อนความจริงและเจาะลึกแก้ปัญหาได้

## สรุปบทที่ 5 (MPM p.90)
- อะไหล่กระทบทั้งงบดุลและงบกำไรขาดทุน
- โรงงานใหม่: เตรียมถูกตั้งแต่ต้น ใช้คำแนะนำผู้ผลิตแต่สอบทานกับตัวอย่างที่ใช้ในไทย; ระดับสะสมต้องมาจากการวิเคราะห์ความวิกฤตรายเครื่อง อาจต้องเตรียมอะไหล่ 100% สำหรับอุปกรณ์วิกฤตสูงสุด
- โรงงานที่เดินเข้าที่: ปรับระดับสะสมทั้ง Quantitative Approach (กลุ่มหมุนสูง) และ Qualitative Approach (กลุ่มหมุนต่ำ)
- โรงงานที่ผลิตมานาน: Optimization ทั้งระบบและทำต่อเนื่อง
- ประเด็นสำคัญ: ระบบรายงานค่าใช้จ่ายอะไหล่ต้องถูกต้อง บางแห่งไม่ชัดจนดูเหมือนค่าซ่อมบำรุงต่ำผิดปกติ (ดู Full Cost ในบทงบประมาณ)
- **ตัวอย่างความคุ้มค่า**: โรงงานใหญ่ค่าบำรุงรักษารวมมากกว่า 50 ล้านบาท มีสัดส่วนอะไหล่ไม่ต่ำกว่า 60-70% คือมากกว่า 30 ล้านบาท; ถ้ายังไม่เคยปรับปรุง มีโอกาสลดได้ 10-15%; ลงทุนปรับปรุง 3-5 ล้านบาท คืนทุนใน 1 ปี
  - ตรวจ (derived): 60% x 50 = 30 ล้าน; 10-15% x 30 ล้าน = 3-4.5 ล้านบาทต่อปี จึงคืนทุนใน 1 ปีเฉพาะเมื่อเงินลงทุนไม่เกินราว 3-4.5 ล้าน (ปลายบน 5 ล้านต้องใช้ฐานอะไหล่ที่สูงกว่า 30 ล้าน หรือ 70% x 50 = 35 ล้าน ได้ 3.5-5.25 ล้าน) ตัวเลขสอดคล้องคร่าว ๆ

- ปัจจัยพร้อมก่อน scheduling (อะไหล่ แรงงาน เครื่องมือ วิธีการ การปล่อยเครื่อง) สอดคล้องกับ 6 องค์ประกอบของ CMRP ใน [[Maintenance Planning and Scheduling]]
- อะไหล่ 60-70% ของค่าบำรุงรักษา (MPM p.90) ตรงกับ RBMM p.34 ใน [[Spare Parts Management]]
- OEE = Availability x Speed x Quality loss 3 ด้าน (MPM p.75) ตรงกับ [[Availability and OEE]]
- Consignment Stock ของ MPM (ผู้ขายเก็บของที่เรา จ่ายเมื่อเบิก) และ Blanket Order = ซื้อก้อนล่วงหน้า ตรงกับศัพท์ของ SPO ใน [[MRO Purchasing and Contracting]]
- สูตร EOQ เทียบเท่าสูตร RBMM/SPO ใน [[EOQ and Reorder Point]] และ [[MRO Inventory Control Methods]] (ต่างแค่ตัวอักษร)
- ABC ไม่สะท้อนราคา/ความวิกฤตรายรายการ (MPM p.87) ตรงกับคำเตือนใน [[MRO Inventory Reduction Program]]

### ขัดแย้ง (CONTRADICTS)
1. **Holding cost**: MPM ว่าค่าเก็บสำรอง **20%-40%** ของมูลค่าอะไหล่ (MPM p.84) ขณะที่ RBMM ของผู้เขียนชุดเดียวกันให้ **15-20%** ต่อปี (RBMM p.16, p.34, p.234) ใน [[Spare Parts Management]] และ [[EOQ and Reorder Point]] — ควรตั้ง `contested: true`
2. **ระดับสต็อกเทียบราคาเครื่องจักร**: MPM ว่าประเทศอุตสาหกรรมเก็บเฉลี่ย **3-5%** ของราคาเครื่องจักร และใช้เป็นดัชนีสอบทาน (MPM p.84-85) ขณะที่ RBMM ตั้งเป้า B7 = 1-3% (RBMM p.295, p.314) และค่าที่ผู้ใช้เลือกแล้ว (resolved 2026-10-27) คือไม่เกิน 4% ของ GPI ตาม SPO (SPO p.115, p.143-145) ใน [[Spare Parts Management]] / [[Inventory Turnover and GPI Benchmarks]] — MPM เป็นค่าเฉลี่ยที่พบ ไม่ใช่เป้า แต่ปลายบน 5% เกินเกณฑ์ที่ผู้ใช้เลือก ควรบันทึกเป็นมุมมองที่ 3 (ฐานต่างกันด้วย: ราคาเครื่องจักร vs GPI)
3. **ความหมาย Blanket Order**: MPM ใช้ Blanket Order = ซื้อเป็นก้อนล่วงหน้า และ Consignment Stock = ผู้ขายเก็บของที่เรา จ่ายเมื่อเบิก (MPM p.88, p.90) ขณะที่ RBMM ของผู้เขียนชุดเดียวกันใช้ "Blanket Order" สำหรับกลไกผู้ขายเก็บของในคลังเรา คิดเงินเมื่อเบิก (RBMM p.289, p.298) — ยืนยันข้อสังเกตเดิมใน [[MRO Purchasing and Contracting]] / [[Spare Parts Management]] ว่าเป็นความต่างของศัพท์ และ MPM เข้าข้างความหมายของ SPO
4. **ABC split และฐาน**: MPM แบ่งตาม **ปริมาณการใช้** A/B/C = 70/20/10% ของการใช้ กับ 10/20/70% ของรายการ (MPM p.87) ขณะที่ SPO ใช้ **มูลค่าการใช้ (ABU)** Fig 10.1 = 80/15/5% ของมูลค่า กับ 20/50/30% ของรายการ (SPO p.115) และ RBMM p.242 ให้ A = 80% ของมูลค่า turnover ใน [[MRO Inventory Reduction Program]] — SPO ระบุว่าสัดส่วนไม่ตายตัว (มี 70/20/10) จึงขัดเรื่องฐาน (ปริมาณ vs มูลค่า) มากกว่าตัวเลข
5. **สัดส่วนเครื่องตามความวิกฤต**: MPM รูปที่ 5.1 = สูง 20% / กลาง 50% / ต่ำ 30% (MPM p.85) ขณะที่ RBMM Fig 1.4 = A 30% / B 50% / C 20% (RBMM p.23-25) ใน [[Criticality Assessment]] — ทั้งสองเป็นตัวอย่าง ไม่ใช่มาตรฐาน แต่กลับด้านกัน; เป้าอะไหล่กลุ่มสูงสุด "เกือบ 100%" ของ MPM สอดคล้องกับ 100% service level ของ RBMM
6. **นิยาม MTBF**: รายงานตัวอย่าง MPM รูปที่ 4.18 คำนวณ MTBF = (ชั่วโมงทั้งหมด - เวลาซ่อม) / จำนวนครั้งเสีย ซึ่งไม่รวมเวลาซ่อม (MPM p.76, derived) ขณะที่ wiki ใช้ MTBF = MTTF + MTTR + MWT ของ RBMM (RBMM p.190-193) ใน [[Reliability Metrics]] — ค่าที่ MPM เรียก MTBF ใกล้ MTTF/MUT มากกว่า (ผลต่างเล็กเมื่อเวลาซ่อมน้อย)
7. **จำนวนจุดอนุมัติใน workflow**: ผัง MPM รูปที่ 4.2 มีจุด "อนุมัติ?" อย่างน้อย 3 จุด (แจ้งซ่อม, เปิด WO, แผนงาน) และรูปที่ 4.4 มีการอนุมัติ WR 2 ชั้น (Owner + Maintenance) (MPM p.62-64) ขณะที่ RBMM Fig 4.10 ระบุว่ามีจุดอนุมัติเพียง 2 จุด (แจ้งซ่อมและปิดงาน) (RBMM p.104) ใน [[CMMS]] — เป็นความต่างของการออกแบบ workflow ตัวอย่าง ไม่ใช่ข้อเท็จจริงขัดกันโดยตรง
8. **สถานะ WO**: MPM ให้ 7 สถานะ (Initiated, Planned, Scheduled, Wait, Issued, Finished, Complete) (MPM p.67-68) ส่วน RBMM Work Backlog Basket = New, Planning, Scheduling, In Progress, In Approval, History + Wait (RBMM p.106) ใน [[CMMS]] — โครงสร้างใกล้กัน ต่างที่ชื่อและการแยก Finished/Complete เป็นสองขั้น (ไม่ใช่ข้อขัดแย้งจริง ระบุไว้เพื่อการเทียบ)
