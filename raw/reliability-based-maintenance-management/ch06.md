# บทที่ 6 งานวิเคราะห์ข้อมูลการเสีย (Failure Data Analysis)

Source: "การจัดการงานบำรุงรักษาด้วย Reliability" (book p.153-178; PDF p155-180, book page = PDF page - 2). PDF p155 = หน้าคั่นบท, p180 = หน้าว่าง

## บทนำบท (book p.154)
- การวิเคราะห์ข้อมูลการเสียเพื่อตัดสินใจเรื่อง maintenance เป็นกระบวนการที่ทำให้วงจรการบริหารสมบูรณ์ แต่เดิมเครื่องมือสถิติมีข้อจำกัด จึงต้องสมมติ Constant Failure Rate ซึ่งใช้ไม่ได้กับทุกกรณี (โดยเฉพาะชิ้นส่วนสำคัญ)
- ปัจจุบันคอมพิวเตอร์/โปรแกรมสำเร็จรูปทำให้วิเคราะห์สถิติได้ง่ายขึ้น แต่ปัญหาคือ "ขาดข้อมูลคุณภาพ"
- วงจรอุบาทว์ (ผู้เขียนเน้น): ไม่วิเคราะห์จริงจัง -> ไม่เห็นความสำคัญของข้อมูล -> ไม่เก็บข้อมูลให้ครบถูกต้อง -> ข้อมูลไม่พอวิเคราะห์ -> วนกลับ
- บทนี้ใช้สถิติ + การตอบคำถามเพื่อให้ตัดสินใจจัดงาน maintenance อย่างเป็นวิทยาศาสตร์

## เหตุปัจจัยที่นำไปสู่การเสียของเครื่องจักร (book p.154-155)
- ทุกชิ้นส่วนมีอายุจำกัด เป้าหมายไม่ใช่ "ไม่ให้เสียเลย" แต่ให้เสียตามธรรมชาติ (Normal Deterioration) ไม่ใช่เสียก่อนเวลาเพราะ Forced Deterioration (การเสื่อมผิดปกติจากเหตุปัจจัยไม่ปกติ) การแก้ที่ถูกคือกำจัดเหตุของการเสียก่อนกำหนด
- สาเหตุหลัก 5 ข้อ:
  1. Failure to observe basic conditions - ไม่ดูแลสภาพพื้นฐาน (สะอาด หล่อลื่น น็อตขาด/หลวม ควบคุมสภาพแวดล้อม) เป็นต้นเหตุที่ป้องกันได้
  2. Failure to observe operating conditions - ใช้งานผิดประเภท/ผิดสเปกที่ออกแบบ เกิดความเครียดเกินกำหนด
  3. Leaving forced deterioration unchecked - ปล่อยการเสื่อมผิดปกติโดยไม่ตรวจ (ต้องมี condition monitoring ติดตามให้ครบ)
  4. Leaving weakness uncorrected - ไม่เข้าใจหรือละเลยแก้จุดอ่อนของเครื่อง
  5. Human error - ผู้ใช้งานและผู้ซ่อม (ซ่อมแล้วสร้างปัญหาใหม่หรือเปล่า)
- การแก้: ข้อ basic condition ต้องเป็นนิสัย/วัฒนธรรม (เปลี่ยนระดับกระบวนการ); ส่วนที่เหลือใช้สถิติ + Reliability Engineering คัดเลือกงานและกำหนดคาบเวลา

## รูปแบบของการเสีย (Failure Patterns) (book p.155-160)
- แต่ละ Failure Mode มีรูปแบบตามธรรมชาติการออกแบบ อธิบายด้วย Failure Rate = ปริมาณการเสียต่อหน่วยเวลา (นึกภาพทดลองใช้ชิ้นส่วนจำนวนมากจนเสียหมด)
- 5 รูปแบบ (กราฟ failure rate vs time, p.155-156):
  - A: ต่ำมากช่วงต้น แล้วเพิ่มอย่างรวดเร็วช่วงปลาย (wear-out ชัดเจน) -> ตัวอย่าง β=15, η=30,000
  - B: อัตราไม่คงที่ เพิ่มไม่มาก (ค่อย ๆ เพิ่ม) -> β=3, η=30,000
  - C: ต่ำช่วงแรก แล้วเพิ่มขึ้นและคงที่ต่อเนื่อง -> β=1.5, η=5,000
  - D: คงที่ตลอด (random) -> β=1, η=5,000
  - E: สูงมากช่วงแรก (infant mortality) ลดเร็วแล้วเข้าสู่อัตราคงที่ -> β=0.5, η=5,000
- เครื่องจักรรวมหลายชิ้นส่วน เมื่อมองระดับเครื่องจะเห็นอัตราเสียรวมสูงช่วงต้นและช่วงปลายอายุ (รูปอ่างน้ำ)
- Weibull มี 3 ตัวแปรสำหรับ maintenance:
  - β (beta) shape parameter = ตัวบอกรูปร่างการกระจาย
  - η (eta) scale parameter = อายุเฉลี่ย/characteristic life (ขนาด)
  - γ (gamma) location parameter = ตำแหน่งเทียบจุดศูนย์ ใน maintenance ตั้ง γ = 0 (ไม่นำมาคิด)
- β กำหนดรูปการกระจาย 3 แบบ:
  1. β > 1: รูประฆังคว่ำ (Fig 6.1) failure rate เพิ่มเร็วเมื่อพ้นจุดหนึ่ง; ช่วง t1 ยังไม่คาดว่าจะเสีย, หลัง t2 ไม่เหลือรอด (no survivors); η มากกว่า (β เท่าเดิม) -> ระฆังแบนกว้างกว่า
  2. β ~ 1: เหมือน Exponential (Fig 6.2; แสดง β=1.0 คงที่ และ β=1.3 เพิ่มช้า) density สูงตอนต้นแล้วลดลง -> failure rate คงที่
  3. β < 1: Hyper-exponential (Fig 6.3) density สูงมากตอนต้นแล้วลดเร็ว -> failure rate ลดลง
- "β และ η ได้มาจากไหน" (p.158): ผู้ผลิตทดสอบอายุ (warranty period) โดยบันทึก (1) เวลาใช้งานจนเสีย (2) Failure Mode; แต่ผู้ผลิตไม่ให้ค่าพารามิเตอร์ (เป็นความลับทางการค้า) หน่วย maintenance ต้องทำย้อนกลับ: เก็บประวัติการเสียของตนเองแล้ววิเคราะห์หา β, η
  - วิเคราะห์ทีละ Failure Mode เสมอ
  - วิธีประมาณ: X หรือ Y Regression, MLE (Maximum Likelihood Estimator) หรือวิธีอื่น แล้วต้องทดสอบ Degree of Fitness
- ภาพประกอบตัวอย่าง (Fig 6.4-6.8; ซ้าย f(t) PDF, ขวา Rate(t)):
  - 6.4 รูปแบบ A (β=15, η=30,000): PDF แหลมแคบ รอบ 20,000-40,000 ไม่มีชิ้นเสียก่อน 20,000 และไม่มีใช้ได้เกิน 40,000; rate พุ่งชันหลัง 20,000 (ในกราฟ rate แกนสูงสุด ~0.0015)
  - 6.5 B (β=3, η=30,000): β ลดแต่ η เท่าเดิม PDF แบนลง การเสียไม่กระจุก ค่าเฉลี่ยยัง 30,000; rate เพิ่มตามเวลา
  - 6.6 C (β=1.5, η=5,000): PDF พีคเร็วแล้วลด; rate เพิ่มช้า ๆ โค้ง
  - 6.7 D (β=1, η=5,000): PDF exponential decay; rate เป็นเส้นแนวนอน (คงที่)
  - 6.8 E (β=0.5, η=5,000): PDF/rate ลดอย่างรวดเร็ว (hyper-exponential)

## หลักการวิเคราะห์ลักษณะสมบัติของการเสียด้วยข้อมูลบำรุงรักษา (Failure Data Analysis) (book p.161)
- Failure Characteristic ของแต่ละ Failure Mode = หาค่าสถิติที่อธิบายพฤติกรรมการเสีย ตัวแปรเหล่านี้นำไปเลือกประเภทงาน PM ที่เหมาะสม แทนการเลือกด้วยความเห็น (ผู้เขียนวิจารณ์ว่าส่วนใหญ่เลือกโดยไม่มีเหตุผล)
- Weibull pdf (3 parameter): f(t) = (β/η) * ((t-γ)/η)^(β-1) * exp(-((t-γ)/η)^β); f(t) = ความหนาแน่นของโอกาสเกิดเหตุการณ์ที่เวลา t
- Fig 6.9 ตัวอย่าง 3 Failure Mode: 2 โหมดที่ β=3.5 แต่ η1 < η2 (กราฟที่ η2 แบนกว่า), อีกโหมด β >> 1 (แหลมสูง) ที่ η2 ; ทั้งหมด β>1; ถ้า η มากกว่า การกระจายความหนาแน่นจะกว้างกว่า; นอกช่วงระฆังไม่มีการเสียของโหมดนั้น
- ข้อมูลที่ต้องมี: (1) Failure Mode/สาเหตุ (2) Time to Fail = อายุใช้งานจนเสียด้วยโหมดเดียวกัน

## การหาตัวแปรสถิติ และใช้ผลวิเคราะห์สนับสนุนการตัดสินใจ (Decision Support by Statistical Analysis) (book p.162)
- หัวข้อที่จะคำนวณ: F(t) (Probability of Failure, B(x)), R(t), Conditional Reliability, MTTF
### การหาค่าตัวแปร Weibull ด้วยกระดาษกราฟ Weibull (p.162-164)
- กระดาษ Weibull ทำให้สมการเป็นเส้นตรง: ln(ln(1/(1-F(t)))) = β ln(t) - β ln(η) (รูป y = ax + c)
- β = slope ของเส้นตรง (อ่านจากสเกล slope บนกระดาษ); η = เวลาที่เส้นตัดที่ probability 63.2%
- ข้อมูล Fig 6.10 (Time to Failure, Median Rank), N=4:
  | j | TTF (ชม.) | Median Rank |
  | 1 | 8,500 | 0.159091 |
  | 2 | 11,000 | 0.386364 |
  | 3 | 12,000 | 0.613636 |
  | 4 | 16,000 | 0.840909 |
- เรียงข้อมูลจากน้อยไปมาก; Median Rank ประมาณด้วย MR(j) = (j - 0.3)/(N + 0.4) (j = ลำดับ, N = จำนวนข้อมูล); MR(1) = 15.9% ฯลฯ คือค่า probability สะสมที่จุดนั้น
- Fig 6.11 อ่านจากกราฟ: β ~ 3.5 (ป้าย B~3.7 บนรูป) และ η ~ 13,000 -- เป็นค่าประมาณจากการลากเส้นด้วยตา

## การอธิบายลักษณะการเสียแบบต่าง ๆ ด้วยตัวแปรสถิติ (book p.165-166)

## การวิเคราะห์ F(t), R(t), Failure Rate, MTTF (book p.166-169)
- Fig 6.15 ผลที่ t=10,000 ชม. (β=3.7888, η=13,130): F = 29.97%, R = 70.03%, λ(t) = 0.0135% ต่อหน่วยเวลา, MTTF = 11,865.51 ชม.
- Probability of Failure: F(t) = integral 0..t f(t)dt = 1 - exp(-(t/η)^β); F(10000) = 1 - exp(-(10000/13130)^3.7883) = 29.97%
- Reliability: R(t) = 1 - F(t) = exp(-(t/η)^β); R(10000) = 70.03% (โอกาสรอดผ่าน 10,000 ชม.)
- Failure Rate (hazard): λ(t) = f(t)/R(t) = (β/η) (t/η)^(β-1) (เครื่องต้องรอดถึง t ก่อน จึงเสียใน dt ได้)
  - ที่ 10,000 ชม. = 0.0135% ต่อหน่วยเวลา
  - กรณี β = 1 (Exponential): f(t) = (1/η)e^(-t/η), R(t) = e^(-t/η) -> λ = 1/η = ค่าคงที่ (Constant Failure Rate); ตัวอย่าง 1/13130 = 0.0000761 = 0.0067%/ชม. ซึ่งใช้ไม่ได้กับตัวอย่างนี้เพราะ β จริงไม่เท่ากับ 1 (ชี้ว่าการสมมติ constant rate ผิดพลาดได้)
- MTTF = integral t f(t) dt = 11,865 ชม. (mean ทางสถิติ ไม่ใช่ arithmetic mean ธรรมดา); ห้ามสับสน: η เป็น MTTF/MTBF ก็ต่อเมื่อ β = 1 เท่านั้น
- (หมายเหตุผู้สรุป: สูตรทั่วไป MTTF = η * Gamma(1 + 1/β); ในหนังสือเขียนปริพันธ์ตั้งแต่ -inf ถึง inf ซึ่งน่าจะพิมพ์คลาดเคลื่อน)

## การคำนวณ Time to Target Reliability (book p.169)
- คือเวลาใช้งานที่ Reliability ลดลงถึงค่าเป้าหมาย; หนังสือพิมพ์สูตร T(R) = η [1 - ln(R)]^(1/β) [สูตรที่ถูกต้องตามทฤษฎีคือ η (-ln R)^(1/β); ผู้สรุปสังเกตว่าตัวเลขในหนังสือสอดคล้องกับสูตรที่พิมพ์ จึงอาจเป็นข้อผิดพลาดของหนังสือ ควรตรวจก่อนนำไปใช้]
- Fig 6.16: target R = 0.8 -> time = 13,847.81 ชม. (ตามที่หนังสือรายงาน)

## การคำนวณ Conditional Reliability (book p.169-170)
- P(t2|t1) = P(t2)/P(t1): โอกาสรอดถึง t2 เมื่อรอดผ่าน t1 มาแล้ว
- Fig 6.17: t1=10,000 (R=70.03%), t2=12,000 (R=49.12%) -> โอกาสรอดจาก t1 ถึง t2 = 70.14%
- การใช้งาน: เครื่องใช้มาแล้ว 10,000 ชม. เหลืออีก 2,000 ชม. ถึง Plant Turnaround/Major Planned Shutdown -> โอกาสรอดถึง shutdown = 70.14% (ใช้ตัดสินว่าเปลี่ยนก่อน turnaround หรือไม่)
## Additional Operating Time of Survival (book p.170)
- ถ้ารอดมา 10,000 ชม. และต้องการโอกาสรอดต่ออีก 80% -> ใช้งานต่อได้อีก 1,369.52 ชม. (Fig 6.18)

## การใช้ข้อมูล Time to Fail ในทางปฏิบัติ (book p.170-172)
- Time to Fail ต้องนับจากเริ่มใช้จนเสียจึงเป็น Complete Data -> ระบบ CMMS ต้องเก็บข้อมูลการเปลี่ยนอะไหล่ถูกต้อง: จุดที่ใช้งาน, เวลาเริ่มใช้, เวลาที่เสียแล้วถูกเปลี่ยน (เสียจริง หรือถูกถอดตามแผน Scheduled PM ก่อนเสีย)
- ถ้าไม่ทราบเวลาเริ่มใช้ หรือยังไม่เสียเมื่อหยุดสังเกต -> อายุไม่ใช่อายุจริง = Incomplete/Censored Data ต้องจัดการให้ถูก (วิธีคิดอยู่บทที่ 12)
- Fig 6.19 ประเภทข้อมูล 6 กรณี (ช่วงสังเกต Beginning Time - End Time):
  1. เริ่มใช้ในช่วงสังเกตและเสียในช่วง -> Complete
  2. ยังใช้ได้เมื่อสิ้นสุดช่วงสังเกต (หรือถูกเปลี่ยนตาม PM) -> Right Censored
  3. Complete เช่นข้อ 1
  4. ไม่ทราบจุดเริ่ม แต่เสียในช่วงสังเกต -> Left Censored
  5. ไม่ทราบจุดเริ่ม และยังใช้ได้ต่อหลังช่วงสังเกต -> (หนังสือเรียก Left Censored; ที่จริงเป็นทั้งซ้ายและขวา)
  6. รู้ว่าเสียในช่วงสังเกตแต่เวลาไม่แน่ชัด -> Interval Censored
- ข้อ (2),(4),(5),(6) = Censored ใช้วิเคราะห์ได้แต่ต้องมีวิธีถ่วงค่าเหมาะสม

## Reliability Block Diagram (RBD) (book p.172-174)
- Reliability ระบบ = ผลรวมของ reliability ชิ้นส่วนย่อย ตามการต่อ
- ต่ออนุกรม (Series; ตัวใดเสีย ระบบเสีย): R_total = R1 x R2 x ... x Rn (Fig 6.20); ตัวอย่าง Fig 6.21: 0.85 x 0.9 = 0.765 (ข้อความหนังสือบอกทั้งสองตัว 0.9 แต่คำนวณด้วย 0.85 -> ใช้ผล 0.765)
- ต่อขนาน (Parallel; ตัวใดตัวหนึ่งรอดระบบยังใช้ได้): R = 1 - PROD(1 - Ri) (Fig 6.22); ตัวอย่าง R1=0.85, R2=0.9 -> 1 - (0.15 x 0.1) = 0.9085 [ค่าที่ถูกคือ 0.985; หนังสือเขียน 0.9085 ซึ่งน่าจะผิดพิมพ์/คำนวณ: 1 - 0.015 = 0.985]
- ต่อผสม (Fig 6.24-6.25): R1=0.85 อนุกรมกับกลุ่มขนาน {R2=R3=R4=0.90} อนุกรมกับ R5=0.80; R* = 1 - (0.1)^3 = 0.999; Rt = 0.85 x 0.999 x 0.8 (= ~0.679)
- ระบบจริงมีชิ้นส่วนมาก ต้องใช้โปรแกรมคอมพิวเตอร์เฉพาะ

## Failure Tree (book p.175)
- ใช้คำนวณ Probability of Failure รวม = 1 - Reliability; ไดอะแกรมตรงข้ามกับ RBD (อนุกรมใน RBD -> ขนานใน failure tree, Fig 6.26)
- Ft = 1 - (1-F1)(1-F2) หรือหลายตัว Ft = 1 - PROD(1 - Fi), โดย Fi = 1 - Ri (ตรงกับสูตร R(t) = R1 x R2) [หนังสือใช้สัญลักษณ์ขนานแทนความหมาย OR-gate]

## Availability (book p.176)
- Availability = สัดส่วนเวลาที่เครื่องพร้อมใช้ (เป็น % ของเวลาที่ต้องการ)
- Reliability บอกโอกาสรอดในเวลาที่กำหนด (reliability ต่ำ = เสียบ่อย); เวลาที่เสียไปคือการสูญเสีย availability ซึ่งขึ้นกับเวลาซ่อมด้วย -> เครื่อง reliability ต่ำแต่ซ่อมเร็วอาจมี availability สูงกว่าเครื่อง reliability สูงที่ซ่อมนาน
- ตัวอย่าง: ใช้ 3 ปี เสีย 3 ครั้ง ครั้งละ 10 ชม. สมมติ constant rate (3 ครั้ง/3 ปี): R(2 ปี) = e^(-2/3) = 51.34%; Availability(3 ปี) = 1 - (3x10)/(3x8760) = 99.89%

## Maintainability (book p.176-177)
- ความสามารถ/ความง่ายในการกลับมาใช้งานได้; ซ่อมนานต่อครั้ง = maintainability ต่ำ
- เวลาซ่อมแต่ละครั้งแปรปรวน (ขึ้นกับ work control, ทีมงาน) จึงใช้ MTTR (Mean Time to Repair) เป็นค่าเฉลี่ย
- ถ้าเวลาซ่อมเป็น Exponential: M(t) = 1 - exp(-t/MTTR); ตัวอย่าง MTTR = 3.5 ชม., t = 3 -> M(3) = 0.5756 = 57.56% โอกาสซ่อมเสร็จใน 3 ชม.
- เปรียบเทียบ maintainability ต้องเทียบภายใต้หน่วยงานบำรุงรักษาเดียวกัน

## สรุปท้ายบท (book p.177)
- การวิเคราะห์เป็นจุดเริ่มต้นของกระบวนการทั้งหมด ถ้าผิด ที่เหลือผิดหมด; CMMS ที่ใช้แค่เปิด/ปิด work order ไร้คุณค่า
- ข้อมูล maintenance แม้ปริมาณไม่มากก็ใช้สถิติได้ เพราะการเสียเป็นไปตามที่ออกแบบ
- ต้องมี Maintenance Engineering กำหนดคุณภาพ/ปริมาณข้อมูลที่ต้องการ ให้ Maintenance Planning เก็บใน CMMS ครบวงจร
- หน้า 178 (PDF p180) = หน้าว่าง

## Links to compressor failure hierarchy / OREDA / ISO 14224
- Failure Mode เป็นหน่วยวิเคราะห์ (ไม่ใช่ตัวเครื่องทั้งหมด): ต้องแยกวิเคราะห์ Weibull ทีละ failure mode -> สอดคล้องกับ failure hierarchy (equipment -> subunit -> maintainable item -> failure mode) และ ISO 14224 ที่บันทึก failure mode + failure mechanism/cause
- Failure causes 5 ข้อ (basic conditions, operating conditions, unchecked deterioration, weakness, human error) ใกล้เคียง failure cause/mechanism classification (ใช้เป็น cause taxonomy เสริมได้ เช่น operating/maintenance error)
- ข้อมูลที่ต้องเก็บใน CMMS: failure mode, Time to Fail (ต้องมีวันติดตั้ง/เริ่มใช้งาน, วันเสีย, ตำแหน่งติดตั้ง), แยก failure vs scheduled PM replacement (suspension/censoring) -- ตรงกับฟิลด์ใน ISO 14224/OREDA (installation date, failure date, operating hours, detection method)
- Censored data (right/left/interval) = แนวคิดเดียวกับ OREDA ที่ต้องจัดการ surveillance period; OREDA ใช้ constant failure rate (exponential) ในตาราง ซึ่งหนังสือชี้ว่าใช้ไม่ได้เมื่อ β != 1 (ควรบันทึกค่า β ด้วย)
- β interpretation (β<1/=1/>1) ใช้จับคู่ failure mode กับกลยุทธ์ RCM (infant mortality/random/wear-out -> เลือก time-based vs condition-based vs run-to-failure) (รายละเอียดบทที่ 8)
- Conditional reliability / additional operating time -> ตัดสินใจเปลี่ยนอะไหล่ก่อน turnaround และวางแผนอะไหล่ (spares) ตาม R(t) ที่ต้องการ
- RBD / Failure Tree เชื่อมกับ criticality และ redundancy (เช่น compressor 2x100%/3x50% ต่อขนาน); Availability/Maintainability (MTTR) ใช้ใน availability analysis
- ไม่มีเนื้อหา FMECA/OREDA ตรง ๆ ในบทนี้; Availability ตัวอย่าง = 1 - downtime/total time
