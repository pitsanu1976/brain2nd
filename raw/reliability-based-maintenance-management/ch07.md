# บทที่ 7 การวิเคราะห์และคัดเลือกงานบำรุงรักษาป้องกัน (Maintenance Task Analysis and Selection)

Source: PDF p181–220 (book p.179–218). p181 = ปกบท; p219–220 = สรุปท้ายบท (book p.218) ซึ่งเป็นหน้าสุดท้ายของบท. หมายเหตุ: ข้อมูลตัวเลขในตัวอย่างบางส่วนเป็นรูปภาพ/screenshot ความละเอียดต่ำ.

## บทนำบท (book p.180)
- ต่อให้ทำ PM ดีเพียงใด ชิ้นส่วนก็ต้องเสียในที่สุด; การเลือกประเภทงาน PM ที่ถูกต้องช่วยหลีกเลี่ยงหรือบรรเทาความเสียหายรุนแรง
- การเสียเกิดจากหลาย Failure Mode จึงต้องทำ Failure Data Analysis ก่อน เพราะบาง Failure Mode แก้ด้วยงานตามแผน (PM) ไม่ได้
- บทนี้เสนอ 3 วิธีเลือกงาน: (1) เลือกแบบง่าย (2) ตามมาตรฐาน SAE JA1011/JA1012 (3) ตามลักษณะสมบัติทางสถิติของ Failure Mode; หลังเลือกประเภทแล้วต้องเลือกคาบเวลา (ใช้การคำนวณทางสถิติ)
- มีการแนะนำโปรแกรมวิเคราะห์งานบำรุงรักษา/อะไหล่ (Simulation) เพื่อช่วยตั้งงบและลดต้นทุน/เพิ่มผลผลิต

## การเลือกงานบำรุงรักษาที่เหมาะสมแบบง่าย (Simplified Maintenance Task Selection) (book p.180)
- อ้างอิงผังของ Nowlan & Heap (1978); ตัวเลือกงานหลัก 5 ประเภท:
  1. Scheduled Condition Monitoring (on-condition)
  2. Scheduled Overhaul หรือ Discard/Replace (scheduled restoration/discard)
  3. Scheduled Failure Finding
  4. Run to Failure
  5. Re-design

### รูปที่ 7.1 ผังการเลือกงานตาม Nowlan & Heap (book p.181)
- ขั้นแรกแบ่ง Evident vs Non-Evident (hidden)
- Evident แบ่งเป็น: Evident Safety; Economic (แยกย่อยเป็น Operational = Op.+Repair และ Non-Operational = Repair only)
- ตัวเลือกงานต่อกลุ่ม:
  - Evident Safety: Condition Monitoring, Restore/Overhaul, Discard/Replace, Combined, Redesign is Required
  - Operational: Condition Monitoring, Restore/Overhaul, Discard/Replace, Run To Failure, Redesign may be desirable
  - Non-Operational: เช่นเดียวกับ Operational (Run to Failure ได้, Redesign may be desirable)
  - Hidden Failure: Condition Monitoring, Restore/Overhaul, Discard/Replace, Failure Finding, Redesign may be desirable

## การคัดเลือกงานบำรุงรักษาป้องกันตามมาตรฐาน SAE JA1011, 1012 (book p.181)
- JA1012 โครงสร้างคล้ายต้นฉบับ Nowlan & Heap; ต่างตรงขยาย Hidden Failure ออกเป็น Economic และ Safety และให้น้ำหนัก Safety และ Environment มากขึ้น
### รูปที่ 7.2 การเลือกประเภท PM ตาม SAE JA1012
- ตัดสินตามลำดับ: Evident/Hidden -> คำถาม Safety? -> Environment? -> Economic (Operational / Non-Operational)
- Evident: Safety -> Condition Monitoring, Restore/Discard, Combination Tasks, Redesign Compulsory; Environment -> เหมือน Safety (Redesign compulsory); Economic-Operational -> Condition Monitoring, Restore/Discard, No Scheduled Maintenance, Redesign may be desirable; Economic-Non-Operational -> เหมือนกัน
- Hidden: Safety -> Condition Monitoring, Restore/Discard, Combination, Failure Finding, Redesign Compulsory; Environment -> เพิ่ม Overhaul/Replace; Economic-Operational -> CM, Restore/Discard, Combination, Failure Finding, No Scheduled Maintenance, Redesign may be desirable; Economic-Non-Operational -> CM, Restore/Discard, Failure Finding, No Scheduled Maintenance, Redesign may be desirable
- ข้อสังเกต: ตัวเลือก "Run to Failure" ใน Nowlan-Heap ถูกแทนด้วย "No Scheduled Maintenance" ใน JA1012

## การเลือกงานบำรุงรักษาตามเงื่อนไขทางเศรษฐศาสตร์และความเป็นไปได้ทางเทคนิค (book p.182–183)
### รูปที่ 7.3 Simplified PM Task Selection Logic (ลำดับถามเรียงตามต้นทุนต่ำไปสูง)
1. Scheduled Condition Monitoring/Inspection ทำได้ทางเทคนิค (Applicable) และคุ้มค่า (Feasible/cost-effective) หรือไม่ -> ถ้าใช่ ทำ Scheduled on-Condition Task (ถูกที่สุดในทุกทางเลือก)
2. ถ้าไม่ -> Scheduled Replacement/Overhaul ทำได้และคุ้มหรือไม่ -> ถ้าใช่ ทำ Scheduled Discard or Restoration Task
3. ถ้าไม่ -> เป็น Hidden Failure หรือไม่ -> ถ้าใช่ ทำ Failure Finding Task
4. ถ้ายังไม่ได้ -> Redesign (จำเป็นเท่านั้น/น่าจะ) หรือ Run to Failure
- Failure Finding PM: คาบการตรวจซับซ้อนกว่า ใช้กับ Protective System/Protective Device (เช่น Protective Relay, Overload Protection, Sequence Protection, Fire Protection)
- Protective System: ตรวจจับความผิดปกติของ Protected Equipment, แจ้งเตือน และ/หรือตัดพลังงาน/แยกระบบอัตโนมัติ เพราะรอคนไม่ทัน
- ปัญหา: อุปกรณ์ป้องกันเสียแบบไม่แสดงอาการ; ถ้าเครื่องที่ถูกป้องกันเสียพอดี = Multiple Failure (ความเสียหายรุนแรง) ดังนั้นการเลือกคาบ Failure Finding ต้องคิดทั้งโอกาสที่ตัวป้องกันเสียเองและโอกาสที่ตัวเครื่องเสีย
- ทางเลือกที่เหลือ: Re-design แบบไม่มีเงื่อนไข ถ้า Failure Mode กระทบ Safety/Environment รุนแรง; Re-design แบบมีเงื่อนไข ถ้าไม่กระทบ; Run to Failure ถ้าไม่มีผลกระทบหรือไม่คุ้มทำอะไร

## การเลือกประเภทงานบำรุงรักษาป้องกันตามลักษณะสมบัติทางสถิติของ Failure Mode (book p.183)
- ต้องมีข้อมูลการเสียและเครื่องมือสถิติ; ใช้ค่า Weibull shape parameter beta (β) เป็นตัวชี้
### ทางเลือกสำหรับ β < 1 (Infant Mortality) (book p.184–185)
- รูปที่ 7.4: PDF และ failure rate ที่ β<1 — failure rate สูงตอนต้นแล้วลดลง
- ภูมิหลัง: เครื่องผลิตถูกควบคุมคุณภาพ ใช้ได้อย่างน้อยถึง Warranty Period; หลังจากนั้นผู้ซื้อทำ PM (Planned) และ CM (Unplanned)
- Infant Mortality = เสียผิดปกติหลัง maintenance ล่าสุดไม่นาน (ชิ้นส่วนที่เพิ่งเปลี่ยน/เพิ่งนำกลับใช้)
- การเสียปกติตามอายุ: β=1 สุ่ม; β>1 พอมองเห็นอายุ; β>>1 มองเห็นอายุชัด (เกาะกลุ่ม)
- β<1 จัดการด้วย PM ไม่ได้ เพราะสาเหตุมาจาก: ใช้อะไหล่ไม่ได้มาตรฐาน, ฝีมือซ่อมไม่ได้มาตรฐาน, ใช้งานไม่ถูกต้อง, สาเหตุอื่น ๆ -> ต้องทบทวนและแก้ที่สาเหตุเหล่านั้น; เสียอาจมาจากตัวงาน PM เองด้วย
### ทางเลือกสำหรับ β = 1 (book p.185–187)
- รูปที่ 7.5: PDF แบบ exponential, failure rate คงที่
- เสียแบบสุ่ม มองไม่เห็นอายุ แต่อายุเฉลี่ยยาวมาก (ตัวอย่าง อุปกรณ์อิเล็กทรอนิกส์ MTBF 15–20 ปี); ต้องเป็นชิ้นส่วนไม่สำคัญหรือ MTBF ยาวมาก, ไม่ควรปนอยู่กับชิ้นสำคัญในกล่องเดียวที่ออกแบบให้ Overhaul
- ทางเลือก: Condition Monitoring (ตรวจค่าใช้จ่ายให้ดี; อิเล็กทรอนิกส์ต้องควบคุมสภาพแวดล้อม เช่น อุณหภูมิ ความชื้น คุณภาพไฟ); Scheduled Replace/Overhaul ไม่ช่วย เพราะบอกอายุไม่ได้
- เตือน: ต้องแยก Failure Mode ให้ชัด; ถ้ารวมหลาย Failure Mode แล้วนับรวม จะได้ β≈1 เสมอ (ข้อผิดพลาดจากการไม่แยก mode)
- กับดัก Overhaul/Replacement เมื่อ β=1 (พิสูจน์ด้วยตัวเลข), R(t)=exp(-t/η):
  - ไม่ทำ Scheduled Replacement: R(120)=47.0158%; R(80)=60.4639%; Conditional Reliability Rc(120/80)=R(120)/R(80)=0.470158/0.604639=77.758%
  - ทำ Scheduled Replacement ทุก 80 ชม.: R(80→120) = R ของชิ้นใหม่ใช้ 40 ชม. = R(40)=77.7585%; R รวม = R(80)xR(40)=60.4639% x 77.7585% = 47.0158%
  - สรุป: ผลเท่ากัน -> constant failure rate การเปลี่ยนตามแผนไม่เพิ่ม Reliability (ค่า η ในตัวอย่างอนุมานได้ราว 160 ชม. [ไม่ได้ระบุชัดในหน้า])
### ทางเลือกสำหรับ β ใกล้เคียง 1 (β -> 1) (book p.187–189)
- รูปที่ 7.6: PDF และ failure rate ที่ β≈1 (failure rate เพิ่มช้าและราบ)
- ชิ้นส่วนไม่สำคัญมาก ผู้ผลิตมั่นใจอายุเลยช่วง warranty; อัตราเสียหลังพ้นประกันสูงขึ้นเล็กน้อย; ตั้งอยู่ในที่เข้าถึง/เปลี่ยนง่าย -> ทางเลือกหลัก = Condition Monitoring
### ทางเลือกสำหรับ β >> 1 (book p.188–189)
- รูปที่ 7.7: PDF แบบระฆังแคบ มี Expected life range ระหว่าง t1–t2; ก่อน t1 ไม่คาดว่าจะเสีย; หลัง t2 ไม่มีรอดเหลือ
- ชิ้นส่วนทนทาน ใช้ร่วมกับชิ้นอื่นที่อายุใกล้กัน ประกอบแน่นในกล่อง (เกียร์, เครื่องยนต์); ผู้ออกแบบต้องระวังไม่ให้มีชิ้น β≈1 ปนอยู่ในกล่อง Overhaul
- 3 ทางเลือก: Condition Monitoring, Part Replacement, Overhaul
- Condition Monitoring ไม่จำเป็นต้องเข้มข้นตอนเริ่มใช้งาน (มีช่วงปลอดบำรุงรักษา) เริ่มช่วงหลังก่อนอายุได้

## การพิจารณาความถี่ของการทำงานบำรุงรักษาป้องกัน (book p.189)
- ประกอบด้วยการวิเคราะห์ 2 ส่วน: CM-Unplanned Analysis และ Scheduled PM Analysis

### การวิเคราะห์งานบำรุงรักษานอกแผน (CM-Unplanned Analysis) (book p.189–190)
- CM-Unplanned (Breakdown) = งานแก้ไขเมื่อเครื่องเบี่ยงเบนจากที่ออกแบบ; ทุกเครื่องต้องเสียในที่สุดจากหลาย Failure Mode
- ผู้ผลิตรู้ Failure Mode ดี (ผ่าน FMECA Process for Design, FMEA for Process); การกำจัดต้นเหตุคือ RCFA (Root Cause Failure Analysis) ซึ่งมีสาระเชิงเทคนิคมาก
- ผู้ผลิตรับผิดชอบเฉพาะช่วง Warranty; ที่ให้ลูกค้าคือ Recommended Maintenance Program (ย้ายภาระค่าใช้จ่ายไปผู้ซื้อ); MTTF ของแต่ละ Failure Mode เป็นข้อมูลที่ผู้ผลิตไม่ค่อยให้ (ความลับทางการค้า)
- หน่วยงานบำรุงรักษาต้องพัฒนาความสามารถวิเคราะห์การเสียเอง (ทำตัวเป็นนักสืบ/หน่วยสืบสวนหาสาเหตุ จัดทำรายการ Failure Mode และปรับ PM ให้เข้ากับสภาพแวดล้อมใช้งานเอง)
- การวิเคราะห์งานซ่อมครอบคลุมค่าใช้จ่าย แรงงาน และผลต่อ Reliability, Availability, Maintainability

### การคำนวณปริมาณงานนอกแผนด้วยค่าเฉลี่ย (Basic Average Method) (book p.190–193)
- สมมติ constant failure rate (pattern D); Weibull β=1, η=λ(=MTBF)
- สูตร: จำนวนครั้งที่คาดว่าเสีย = ระยะเวลาที่กำหนด / อัตราการเสียเฉลี่ย (MTBF) — ใช้ได้เฉพาะ pattern D ไม่ใช่อีก 4 รูปแบบของบทที่ 6
- ตัวอย่าง รูปที่ 7.8 (timeline: 16000 ชม. ทำงาน, ซ่อม 10, 12000, ซ่อม 12, 11000, ซ่อม 8, 8500, ซ่อม 10, 300 ชม. สุดท้ายยังใช้งาน):
  - วิธี 1: ช่วงสังเกต 47,840 ชม., เสีย 4 ครั้ง -> เฉลี่ย 47,840/4 = 11,960 ชม. -> ใน 3 ปี = 3x(8760/11,960) = 2.20 ครั้ง
  - วิธี 2: MTBF = MTTF + MTTR + MWT (รูปที่ 7.9; TTF, DT = WT + RT); MTTF=(16000+12000+11000+8500)/4=11,875 ชม. (ตัด 300 ชม. สุดท้ายออกเพราะยังไม่เสีย); MTTR+MWT=(10+12+8+10)/4=10 ชม.; MTBF=11,885 ชม. -> 3x(8760/11,885)=2.21 ครั้ง
  - ผลต่างน้อยเพราะช่วงสังเกตยาว
- วิธีใช้ข้อมูลรวมจำนวนมาก (รูปที่ 7.10): 100 หน่วย x 43,800 ชม. (5 ปี) = 4,380,000 unit-hrs; เสีย 11 ครั้ง (ไม่แยก Failure Mode) -> MTBF=398,181.82 ชม.
  - 15 หน่วยใน 3 ปี (26,280 ชม.) = 394,200 unit-hrs -> 0.99 ครั้ง; ตัวอย่างในเนื้อหา 20 เครื่อง: 525,600/398,181.82 = 1.32 ครั้ง ~ 1 ครั้งใน 3 ปี
  - ข้อควรระวัง: ค่าเฉลี่ยคำนวณจากทุก Failure Mode รวมกัน จึงดูเหมือน β=1 เสมอ; ใช้ด้วยความระมัดระวัง ควรเทียบกับวิธีสถิติ

## Advanced Maintenance Analysis and Management (book p.193–218)
- คอมพิวเตอร์ที่ทรงพลังและการเชื่อมข้อมูลซ่อมกับระบบ ERP ทำให้ประยุกต์ Reliability Engineering ได้เต็มรูปแบบ (Maintenance Incidence Analysis) ด้วยแบบจำลองสถิติ/คณิตศาสตร์ขั้นสูงซึ่งคำนวณมือไม่ได้
- ผู้ใช้ไม่จำเป็นต้องรู้ว่าโปรแกรมสร้างอย่างไร (เทียบกับ Excel, Word) ให้มุ่งที่เนื้อหางาน

### การคำนวณโดยใช้สถิติและแบบจำลอง (Statistics and Simulation Model) (book p.194–195)
- รูปที่ 7.11: TTF, Wait Time, Time to Repair เป็นตัวแปรสุ่มมีการแจกแจงเป็นระฆังคว่ำ; ค่าเฉลี่ย = MTBF, MTTR, MWT (MTTF, MTTR, MWT ตามรูป)
- ข้อกังวลเรื่องข้อมูลน้อยเกินไป: ชิ้นส่วนถูกออกแบบ/ทดสอบแล้ว Failure Mode จึงเป็น "Man-made Pre-programmed Failure" (เสียแบบจัดทำล่วงหน้า) ทำให้ใช้ข้อมูลน้อยก็พอประมาณพารามิเตอร์ได้ (ตัวอย่างแบริ่งเสียที่ 2 ปี: คาดว่าไม่น่าเสียก่อน 1 ปีหรือเกิน 3 ปี)
- สถิติคำนวณได้เฉพาะโอกาสเสีย F(t) และ Reliability R(t) ไม่ใช่จำนวนครั้งที่เสีย (ตัวอย่างโยนเหรียญ 20 vs 1,000 ครั้ง, Confidence Level) -> ต้องใช้ Simulation Model
- โปรแกรมตัวอย่าง: Minitab, MathCad, CEDAR Maintenance Optimizer, Weibull Smith; ความท้าทายคือต้องเข้าใจ RCM, Failure Mode, FMECA, Statistics, Data Mining, Optimization, Spare Part Stock Max/Min, Demand/Supply Side, Costing Accounting, Risk พร้อมกัน; การเรียนจากโปรแกรมสำเร็จรูปเร็วกว่า

### การคำนวณโดยใช้ Simulation Model (book p.196–197)
- Deterministic/Parametric Model (รูปที่ 7.12): input x1..x3 -> f(x) -> output y1,y2 เป็นค่าแน่นอน
- Monte Carlo Simulation (รูปที่ 7.13): input เป็นการแจกแจงสถิติ สุ่มด้วย random number หลายรอบแล้ววิเคราะห์ผลลัพธ์ทางสถิติ (ตัวอย่าง output Reliability = 87%)
- ใช้วิเคราะห์ PM และระดับอะไหล่ที่เหมาะสมพร้อมความเสี่ยง โดยนำ MTTR, MWT, Lead Time, ราคาอะไหล่, ค่าใช้จ่าย, ข้อมูลใช้อะไหล่และการเสีย มาเป็นอินพุต; อ้างอิงบทที่ 4 (Computerized Risk Based Spare Part Optimization) และบทที่ 9 (การบริหารอะไหล่)

### การวิเคราะห์งานนอกแผน (CM-Unplanned Analysis) ด้วยแบบจำลอง (book p.198–199)
- แต่ละงานซ่อม = Maintenance Incidence วิเคราะห์ราย Failure Mode; เริ่มด้วยหาพารามิเตอร์ Weibull ของ Dominant Failure Mode

### Scheduled PM ประเภท Condition Monitoring (book p.207–212)
- Pattern A/B (β>>1) มีอาการล่วงหน้า -> ใช้ Condition Monitoring/Inspection แล้วเปลี่ยนเมื่อตรวจพบ
- รูปที่ 7.24: แบ่งอายุ 3 ช่วง: (1) ไม่น่าเสีย F(t)<0.01 ไม่ต้องทำ CM PM; (2) เริ่มมีเสียเล็กน้อย F(t)<0.1 ยังไม่ต้องทำเต็มรูปแบบ; (3) น่าเสีย F(t)>0.1 ต้องทำ Condition Monitoring PM เต็มรูปแบบ
- CM PM ราคาถูกมักใช้แรงงานภายใน ข้อจำกัดคือ Utilization และเครื่องมือ
- ช่วงเวลา P-F (Potential Failure Interval) (รูปที่ 7.25): ช่วงจากจุดเริ่มตรวจพบอาการ (เช่น สั่นเกิน/สึกหรอ) ไปจนเสียจริง; มี P-F ที่สั้นที่สุด (F1 vs F2); ต่างจาก PDF (PDF = การกระจายเวลาเสีย; P-F curve = เวลาจากเห็นอาการถึงเสียจริง)
- Threshold of Life / Threshold Period = อายุที่ใช้งานมาก่อนเริ่มกระบวนการสิ้นอายุ (เป็น % ของอายุ)
- รูปที่ 7.26: จุด P (Potential Failure) -> F (Functional Failure); CM ที่ตรวจพบก่อน F เปลี่ยนเป็น CM-Planned; ตรวจที่คาบ PF/2
- รูปที่ 7.27: Total Maintenance = Preventive + Corrective-Planned + Corrective-Unplanned; output: จำนวนครั้ง CM-Unplanned, PM, CM-Planned, Availability, ค่าใช้จ่ายต่อหน่วยเวลา, ค่าใช้จ่ายรวม
- คาบตรวจห่างเกินไปอาจพลาด (เสียก่อนวัดครั้งต่อไป) ที่ถี่เกินสิ้นเปลือง; ปัจจัยสำคัญ 2 อย่าง = PF Period และเงื่อนไขตรวจว่ามีอาการแล้วหรือยัง; เมื่อพบต้องรีบเปลี่ยนภายใน PF Period
- ตัวอย่าง Simulator (รูปที่ 7.28–7.30): P-F = 4 เดือน (120 วัน), ทดลองคาบ 10 วัน เพิ่มทีละ 5 วัน; ค่าใช้จ่าย PM 1,600 บาท/ครั้ง; CM-Planned 570,000 บาท/ครั้ง; CM-Unplanned 570,000 บาท/ครั้ง [ตัวเลขจากหน้า 211; อ่านจากหน้ากระดาษตัวพิมพ์]
  - ผล: คาบสั้นกว่า 120 วันมีโอกาสดักจับได้; CM-Unplanned เริ่มมีนัยสำคัญที่คาบ ~45-50 วัน; ตรงกับหลัก คาบ = (P-F)/2 = 60 วัน; คาบ>60 วัน CM-Unplanned เพิ่มขึ้น จน 120 วันเพิ่มเร็วมาก (รูปที่ 7.29 สเกล 30–160 วัน, รูปที่ 7.30 ขยาย 100–160 วัน เห็น Total cost พุ่งเมื่อ >120 วัน, CM-Planned ลดลง)

### Scheduled PM ประเภท Failure Finding (book p.212–215)
- Failure Finding ตรวจ Hidden Failure ของ Protective Device/System (Protective Relay, Breaker, Switch Gear; ตัวอย่างบ้าน: ตัวป้องกันไฟรั่ว/ไฟดูด)
- รูปที่ 7.31: ตัวป้องกันเสียแบบซ่อน -> ถ้าเครื่องเสียพอดี = Multiple Failure ความเสียหายควบคุมไม่ได้
- หลักตาม SAE JA1012 (รูปที่ 7.32): Unavailability of Protective Function = 0.5 x FFI / MTBF ของอุปกรณ์ป้องกัน (M_TIVE); FFI = 2 x Unavailability x M_TIVE; ช่วง Unavailability คือ B–C (ตัวป้องกันเสียแล้วตรวจไม่พบ), FFI คือ A–C
- รูปที่ 7.33: Availability ที่ต้องการ -> FFI (% ของ MTBF): 99.99% -> 0.02%; 99.95% -> 0.1%; 99.9% -> 0.2%; 99.5% -> 1%; 99% -> 2%; 98% -> 4%; 95% -> 10%
- เชื่อมกับ Multiple Failure (รูปที่ 7.34): M_TED = MTBF ของเครื่องจักรที่ถูกป้องกัน; M_MF = MTBF ของ Multiple Failure; M_TIVE = MTBF ของอุปกรณ์ป้องกัน; Probability เสียใน 1 หน่วยเวลา = 1/MTBF
  - 1/M_MF = (1/M_TED) x U_TIVE
  - U_TIVE = M_TED / M_MF
  - FFI = 2 x U_TIVE x M_TIVE = 2 x M_TIVE x M_TED / M_MF
- ข้อจำกัด: ได้ข้อมูลครบยาก และการเสียไม่ใช่ constant failure rate -> Simulation ดีที่สุด

### PM สำหรับระบบที่มีเครื่องจักรสำรอง (Redundancy) (book p.215–218)
- เพิ่มความน่าเชื่อถือ 2 วิธี: ใช้เครื่องที่ reliable สูง และให้มี Redundancy
- k out of n: ต้องการ k จาก n หน่วย (เช่น 1 out of 2 = 1/2); รูปที่ 7.35: อุปกรณ์สลับเปลี่ยน X ตรวจสถานะเครื่องและต่อสำรองอัตโนมัติ/ด้วยมือ
- ข้อพิจารณา:
  - แผนการใช้งาน (Operating plan): เครื่องที่ใช้มากเสี่ยงเสียมากกว่า; ควรให้อายุใช้งานต่างกันเพื่อลดโอกาสเสียพร้อมกัน; สลับตามสัดส่วน เช่น 80/20 หรือ 60/40 พร้อมทดสอบเครื่องสำรอง
  - แผนงาน PM: ประกอบด้วยเครื่อง n เครื่อง + อุปกรณ์สลับเปลี่ยน; อุปกรณ์สลับเปลี่ยนต้องใช้ Failure Finding (hidden failure เหมือน protective device); เครื่อง n เครื่องเลือกงานได้ทุกประเภทโดยพิจารณา Multiple Failure เป็นหลัก (เครื่องสำรองเสียแบบซ่อนเมื่อไม่ได้ใช้)
  - รูปที่ 7.36–7.37: แต่ละ Failure Mode (β, η) ของแต่ละเครื่อง (FM1, FM2, FM3...) มี Maintenance Policy ของตัวเอง + FM ของตัวสลับ (FMsw) แล้วรวมเป็น Total R(t) ของระบบ k/n
  - ขั้นตอน: เริ่มจาก Dominant Failure Mode; วิเคราะห์ข้อมูลเสียรายเครื่อง/ราย Failure Mode; เลือกงานและคาบ PM ต่อ Failure Mode; วิเคราะห์ Reliability รวมด้วย Monte Carlo Simulation; ปรับคาบ PM ให้ระบบรอดตามแผนการใช้งาน

## สรุปท้ายบท (book p.218)
- การจัดการงานบำรุงรักษาต้องเน้นงานตามแผนที่มีประสิทธิผลเพื่อลดผลกระทบจากการเสีย; ต้องมีข้อมูลทั้งเทคนิคและค่าใช้จ่ายที่ครบถ้วน เก็บให้น่าเชื่อถือ แล้ววิเคราะห์อายุชิ้นส่วน หา parameter ทางสถิติ แล้วเลือกประเภทงานและคาบที่เหมาะสม

## Links to compressor failure hierarchy / OREDA / ISO 14224
- ตรรกะเลือกงาน PM (รูปที่ 7.1–7.3) สอดคล้อง RCM decision logic ที่ผูกกับ Failure Mode/Consequence (safety, environment, economic/operational, hidden); ใช้ต่อยอดเป็นคอลัมน์ "recommended task type" ใน failure hierarchy ของคอมเพรสเซอร์ (เช่น seal, bearing, valve, protective trip)
- Failure Mode ราย mode ต้อง fit Weibull (β, η) แยก; การไม่แยก mode ทำให้ β≈1 ผิดพลาด -> เกี่ยวกับการลงรหัส Failure Mode/Failure Mechanism/Cause ใน CMMS ตาม ISO 14224 และการใช้ OREDA เป็น generic failure rate (constant, pattern D) เปรียบเทียบกับข้อมูล site-specific (β>>1)
- ข้อมูลที่ต้องเก็บใน CMMS: TTF ราย Failure Mode (ตัด censored interval สุดท้ายออกจาก MTTF), MTTR, MWT, ค่าอะไหล่, ค่าแรง, อัตราสูญเสียหยุดเครื่อง (p.190–203) — ตรงกับ ISO 14224 maintenance data (downtime, active repair time) และ OREDA
- Failure rate รวมแบบ pooled (100 หน่วย 43,800 ชม. 11 เสีย) เป็นหลักคิดเดียวกับ OREDA (การประมาณ MTBF จาก calendar/operating time ต่อจำนวน failure)
- FMECA/FMEA/RCFA กล่าวถึงเป็นกระบวนการผู้ผลิตและงานสืบหาต้นเหตุ (p.189) ส่วน Criticality ใช้จัดลำดับ Dominant Cost/Problem Drivers และครอบคลุม ~80% (p.206)
- Protective devices (relay, breaker, trip/shutdown systems) ใช้สูตร FFI = 2 x U x MTBF_protective และตาราง Availability->FFI (p.213–215) — ใช้กับ compressor protection/ESD/PSV proof-test interval (คล้าย SIL proof-test, แต่หนังสือไม่ได้อ้าง IEC 61508)
- Spares: ผล Simulation ให้จำนวนครั้ง CM-Unplanned + Scheduled PM -> demand ตั้ง Max/Min ตาม Lead Time (p.201–206; อ้างบทที่ 4 Risk Based Spare Optimization และบทที่ 9)
- Redundancy (k out of n, หน่วยสำรอง/switch): standby compressor A/B ต้องมี Failure Finding บนตัวสลับ/เครื่องสำรอง, สลับรันสัดส่วน 80/20 หรือ 60/40 พร้อมทดสอบสำรอง (p.216–218)
