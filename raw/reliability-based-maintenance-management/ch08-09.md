# บทที่ 8 การจัดการงานบำรุงรักษาป้องกันตามแผนให้ได้ประโยชน์สูงสุด (Scheduled Maintenance Optimization)

## บทนำ (book p.220)
- คาบเวลา (interval) ของงานบำรุงรักษาทุกประเภทต้องเลือกให้เหมาะสม: PM ถี่เกินไป = ค่าใช้จ่ายสูง, น้อยเกินไป = หยุดค่าซ่อมไม่ได้
- ต้องกำหนดก่อนว่า objective คืออะไร: ต้นทุนบำรุงรักษาต่ำสุด หรือ availability สูงสุด หรือเงื่อนไขอื่น
- การคำนวณต้องรวมทั้งค่าใช้จ่ายทางตรง (ค่าซ่อม) และทางอ้อม (ความเสียหายจากการหยุดเครื่อง ทั้งหยุดตามแผนและนอกแผน)

## กระบวนการทำ Scheduled PM Optimization (book p.220-221)
- รูปที่ 8.1: กระบวนการเลือกงาน PM และจัดคาบให้เหมาะสม เป็นส่วนหนึ่งของกระบวนการบริหารทั้งหมด. แผนผังมี 5 คอลัมน์ภายใต้ CMMS Process (Work Control, Scheduled PM, Spare Part Control):
  | คำถาม | กระบวนการ | ผลลัพธ์ |
  |---|---|---|
  | PM Selection? | RCM Process (เลือกงานตามความวิกฤติของเครื่องจักร) | RCM Scheduled PM Tasks |
  | Optimum PM Interval? | PM Optimization (จัดงานให้ได้ประโยชน์สูงสุด) | Scheduled PMs at Optimum Interval |
  | Stock Performance? | Risk Based Spare Part Optimization (จัดตั้งอะไหล่สำรองคลังให้ได้ประโยชน์สูงสุดภายใต้ความเสี่ยงที่กำหนด) | ระดับอะไหล่คงคลังที่ได้ประโยชน์สูงสุด |
  | Budgeting & Control? | Performance Budgeting (เครื่องจักรทำงานได้ไม่หยุดตลอดเวลาที่กำหนดด้วยต้นทุนต่ำสุด) | งบประมาณตามเป้าหมาย |
  | Problem of Reporting? | Maintenance Strategic Report (Accountability, Responsibility) | Strategic Reporting Items |
  - ผลทั้งหมดส่งขึ้น Management ผ่าน Maintenance Management Report และดัชนีวัด
- การ optimize ที่ครบถ้วนต้องรวมต้นทุนเตรียมอะไหล่ด้วย เพราะระดับอะไหล่สะสมกำหนดว่า CM-Unplanned รับมือได้แค่ไหน; ถ้า optimize ที่จุดที่ยอมให้เสียได้ ก็ต้องยอมรับความเสี่ยงอะไหล่ไม่พอเมื่อเกิดงานซ่อมนอกแผน

## การจัดงานบำรุงรักษาป้องกันให้ได้ประโยชน์สูงสุด (Planned Maintenance Optimization) (book p.221-223)
- รูปที่ 8.2 Maintenance Incidents แตกเป็น 2 ฝั่ง: (1) Scheduled PM + CM-Planned (2) CM-Unplanned (ขีดฆ่า = สิ่งที่อยากลด)
  - งานตามแผน 4 แบบ: Scheduled Inspections/Condition Monitoring, Scheduled Replacement, Scheduled Overhaul, Scheduled Failure Finding
  - Inspection/CM และ Failure Finding "ดักจับ" potential breakdown ให้กลายเป็น CM-Planned (Intercepted Potential Breakdowns)
  - CM-Unplanned ต้องใช้ resources (Parts, Labors) แบบฉุกเฉิน
- ทางเลือกต่ำสุดคือ Run to Failure (ทำ CM-Unplanned อย่างเดียว) ต้องแยกวิเคราะห์ตาม Failure Mode: เลือกงานที่สกัดหรือลดความเสียหายจากงานนอกแผนได้ แล้วหาความถี่ที่ให้ประโยชน์สูงสุด. สถิติ (failure behaviour ต่อ Failure Mode) เป็นตัวชี้นำชนิดงานที่เหมาะสม
- เครื่องจักรวิกฤติระดับ A บางกรณียอมทำตามแผนมากจนไม่มี failure เลย ยอมรับต้นทุนนั้น
- เงื่อนไข optimize ที่เป็นไปได้: (1) total cost (planned + unplanned) ต่ำสุด (2) Availability สูงสุด (3) Reliability, Maintainability สูงสุด. บางกรณี Re-design คือทางที่ดีที่สุด
- ปัจจัยที่องค์กรต้องมี: ระบบคิดค่าใช้จ่ายครบถ้วน, รายงานดี, ความรู้ Reliability Engineering/สถิติ, ข้อมูลประวัติซ่อมถูกต้อง; ควรฝังความรู้ในระบบ/Work Process ไม่ใช่ผูกกับตัวบุคคล
- รูปที่ 8.3 (book p.222): แกน X = PM Interval, แกน Y = Cost. เส้น Planned Maintenance ลดลงเมื่อ interval ยาวขึ้น, เส้น Unplanned Maintenance เพิ่มขึ้น, ผลรวม (Total Cost/Up Time) เป็นรูปตัว U; จุดต่ำสุดของผลรวม = optimum
- จุด optimum ไม่ใช่จุดที่ planned cost = unplanned cost เพราะความสัมพันธ์ไม่เป็น linear
- ถ้าอัตราการเสียคงที่ (Constant Failure Rate / random failure) จะหาจุด optimum ไม่ได้ การเปลี่ยนชิ้นส่วน/overhaul ตามกำหนดจึงไม่ได้ผล
- Optimum = จุดที่ cost รวมต่อหน่วยเวลาต่ำสุด; ต้องรู้ cost ต่อครั้ง และโอกาสเกิดของ PM และ CM

## การจัดงาน PM แบบ Part Replacement หรือ Overhaul ให้ได้ประโยชน์สูงสุด (book p.223-226)
- รูปที่ 8.4: PDF f(t) ของ failure mode หนึ่ง; ตัดที่ tp (เวลา PM): พื้นที่ขวา tp = R(tp) = โอกาสรอดถึง tp (อีกฝั่ง = 1 - R(tp) = probability of failure ก่อน tp); M(tp) = เวลาเฉลี่ยที่เสียหากเสียก่อน tp
- สัญลักษณ์: Cp = ค่าใช้จ่ายทำ PM 1 ครั้ง; Cf = ค่าใช้จ่ายเมื่อเกิด CM (failure) 1 ครั้ง; C(tp) = ค่าใช้จ่ายรวมต่อหน่วยเวลาเมื่อ PM ที่ tp; R(tp) = reliability ที่ tp; tp = คาบ PM
- สูตรหลัก (cost per unit time):
  - (ค่าใช้จ่าย PM x โอกาส + ค่าใช้จ่าย CM x โอกาส) / (คาบ PM x โอกาส + คาบ CM x โอกาส)
  - (1) C(tp) = [Cp*R(tp) + Cf*(1-R(tp))] / [tp*R(tp) + M(tp)*(1-R(tp))]
  - M(tp) = (integral 0..tp of t*f(t) dt) / (1 - R(tp))
  - (3) C(tp) = [Cp*R(tp) + Cf*(1-R(tp))] / [tp*R(tp) + integral 0..tp of t*f(t) dt]   (ตัว (1-R) ตัดกับตัวหารของ M(tp))
  - ความหมายพจน์: Cp*R = ค่า PM ที่คาดว่าจะเกิด; (1-R) = โอกาสเสียก่อน tp; Cf*(1-R) = ค่าซ่อมนอกแผนที่คาดว่าจะเกิด; tp*R = เวลา PM ที่คาด; M(tp)*(1-R) = เวลาทำงานนอกแผนที่คาด
- ตัวอย่างเชิงตัวเลข (Weibull): beta = 3.7888, eta = 13,130 ชั่วโมง (ใน MathCAD ใช้ eta = 13130.8/24.30 หน่วยเดือน), Cf = 2,070,000, Cp = 360,000 (บาท). f(t) = (beta/eta)*(t/eta)^(beta-1)*exp(-(t/eta)^beta); F(t)=integral f; R=1-F
- รูปที่ 8.5 (MathCAD): กราฟ c(t) ต่อ t = 0-40 เดือน; ต่ำสุดที่ประมาณ 10 เดือน (ค่า c(t) ประมาณ 5x10^4), แล้วเพิ่มขึ้นและราบที่ประมาณ 1.25x10^5 เมื่อ t > 28 (กลายเป็น run-to-failure)
- ข้อสังเกต: เป็นการแก้สมการตรง ใช้เฉพาะค่าสถิติ + cost ต่อครั้ง; ตั้งสมมติฐานว่าเวลาซ่อม (MTTR, MWT) เป็นศูนย์ จึงไม่ถูกต้อง 100%

## ข้อควรพิจารณาในการจัดงานบำรุงรักษาให้ได้ประโยชน์สูงสุด (book p.231-232)
- อุปสรรค: (1) อาจทำไม่ได้กับทุก Failure Mode (2) failure pattern ประเภท B, C, D (อัตราเสียคงที่/ค่อนข้างคงที่ = random failure) optimize PM ไม่ได้ (3) ถ้าอัตราส่วน unplanned cost ต่อ planned cost ต่ำเกินไปหรือต่างกันน้อย การปรับคาบไม่ส่งผล; ถ้าทำเองด้วยหน่วยงานภายใน (fixed cost) การปรับถี่/ห่างกระทบแค่ Utilization Factor ไม่กระทบ Full Fixed Cost (4) เครื่องที่มี Redundancy (1 ใน 2, 2 ใน 3) ต้องพิจารณาให้ถูก
- Redundancy: optimize รายเครื่องไม่เท่ากับ optimize ระบบ; เครื่องสำรองอาจมี Hidden Failure => Multiple Failures เมื่อเครื่องหลักหยุด ต้องวิเคราะห์ความเสี่ยงที่ระบบทำงานไม่ได้; เป้าหมายอาจเป็นความมั่นคงของระบบมากกว่าต้นทุนต่ำสุด
- การเดินเครื่องที่ถูกต้อง: ไม่ใช้เครื่องหลัก/สำรองสลับเท่า ๆ กัน (จะเสียไล่เลี่ยกัน) ควรใช้สัดส่วน 60/40 หรือ 80/20 ให้ชิ้นแรกเหลือเวลาซ่อม พร้อม Condition Monitoring และ Failure Finding เพื่อหา Hidden Failure โดยเฉพาะอุปกรณ์ Transfer Switch อัตโนมัติ
- สะสมอะไหล่อาจไม่จำเป็นถ้า Lead Time ไม่ยาวเกิน
- Model/Monte Carlo ใช้ได้กับ PM ประเภทอื่น เช่นคาบของ Condition Monitoring หรือ Part Replacement

## สรุปท้ายบท (book p.232)
- มีทั้งแบบแก้สมการตรง (Simultaneous Equation) และ Monte Carlo Simulation; ที่สำคัญคือ cost ต่อครั้งของ planned/unplanned และประวัติบำรุงรักษาที่ถูกต้อง
- การ optimize ทำไม่ได้ทุกกรณี; จุดตั้งต้นที่สำคัญกว่าคือการวางกลยุทธ์ตามความวิกฤติของเครื่องจักร/ระบบ

## Key terms (บทที่ 8)
- Scheduled PM Optimization — การจัดคาบ PM ให้ได้ประโยชน์สูงสุด — หาคาบที่ total cost (planned + unplanned) ต่อหน่วยเวลาต่ำสุด — p.220
- Run to Failure — ปล่อยให้เสียแล้วซ่อม — ทำ CM-Unplanned อย่างเดียว — p.221
- CM-Planned / CM-Unplanned — ซ่อมตามแผน / ซ่อมนอกแผน — CM-Planned เกิดจากการตรวจพบก่อนเสียจริง — p.221
- Scheduled Replacement / Overhaul / Failure Finding / Inspection-Condition Monitoring — ประเภทงาน PM ตามแผน — p.221
- Cp / Cf — ต้นทุน PM ต่อครั้ง / ต้นทุน failure (CM) ต่อครั้ง — p.224
- C(tp) — cost per unit time ที่คาบ tp — สูตรค่าใช้จ่ายคาดหวัง/เวลาคาดหวัง — p.224-225
- R(tp), M(tp) — reliability ที่ tp, mean time to failure เมื่อเสียก่อน tp — p.224-225
- Weibull beta/eta — ตัวแปรรูปร่าง/ขนาดของ failure distribution — p.225
- Item Age vs System Age replacement — เปลี่ยนตามอายุชิ้นส่วน vs อายุระบบ — p.227-230
- Monte Carlo Simulation — การจำลองสุ่มเพื่อหา interval — p.227
- Constant Failure Rate / Random Failure — อัตราเสียคงที่ — optimize PM ไม่ได้ผล — p.223, 231
- Redundancy / Hidden Failure / Multiple Failures — เครื่องสำรอง / เสียแบบไม่แสดงอาการ / เสียซ้อน — p.231
- Utilization Factor, Full Fixed Cost — p.231

## Links to compressor failure hierarchy / OREDA / ISO 14224
- Failure mode เป็นหน่วยวิเคราะห์ของ optimization (แยก tp ต่อ failure mode ต่อ component) - สอดคล้องกับระดับ failure mode ใน ISO 14224 / OREDA taxonomy; ต้องได้ beta/eta ต่อ failure mode จากข้อมูลประวัติซ่อม (OREDA ให้ failure rate/ MTTF ระดับ item ส่วนใหญ่เป็น constant rate จึงใช้หา tp ไม่ได้ ตาม p.223/231)
- Failure pattern A-F (หนังสืออ้าง B, C, D = random) เชื่อมกับ RCM; งาน PM เลือกจาก failure mode/mechanism
- CMMS ต้องบันทึก: ค่าใช้จ่ายต่อครั้ง planned/unplanned, MTTR/MWT, failure mode, failure date เพื่อทำ optimization (p.229)
- เครื่องจักรวิกฤติระดับ A / Redundancy / Hidden Failure (Transfer Switch) เชื่อมกับ criticality และ FMECA (p.221, 231-232)
- Condition Monitoring / Failure Finding เป็นงานดัก potential failure -> CM-Planned (p.221)

# บทที่ 9 การลดและจัดอะไหล่คงคลังให้ได้ประโยชน์สูงสุด (Risk Based Spare Part Reduction and Optimization)

## บทนำ (book p.234)
- อะไหล่เป็นปัจจัยเชิงกลยุทธ์: ต้นทุนบำรุงรักษามากกว่าครึ่งเป็นค่าอะไหล่; ค่าใช้จ่ายสะสมอะไหล่ (holding) อาจสูง 15-20% ของมูลค่าอะไหล่ต่อปี (ตัวอย่างหนังสือ: สต็อก 500 ล้านบาท -> ค่าใช้จ่าย 75-100 ล้านบาท/ปี ไม่นับสภาพคล่อง)
- อะไหล่น้อยไป = เสี่ยงสูญเสียผลิต/ตื่นตระหนกสะสมมาก; มากไป/ผิดตัว = Write-off
- ต้องบริหารทั้ง Supply Side และ Demand Side; การลดอะไหล่คงคลังต้องทำคู่กับ Planned Maintenance Optimization
- แบ่งงานอะไหล่เป็น 2 ส่วน: Commissioning Spare Part และ Maintenance Spare Part

## Risk Based Spare Part Reduction and Optimization (book p.234)
- ประเด็นสำคัญ: อะไหล่สำหรับ Unplanned Maintenance ซึ่งความต้องการไม่แน่นอน; ต้องตั้งระดับสำรองโดยพิจารณาความเสี่ยง ใช้สถิติและคอมพิวเตอร์

## การจัดการอะไหล่สำหรับงาน Commissioning (book p.235)
- ช่วง commissioning เครื่องเพิ่งประกอบ ไม่เคยทำงานร่วมกัน; มักเปลี่ยนไปใช้ของราคาถูกกว่าตามแรงกดดันเรื่องราคา; ความเสียหายส่วนใหญ่มาจากฝีมือประกอบ (construction)
- ผู้ขายใช้โอกาสนี้ขายอะไหล่เกินจำเป็น (อาจเกิน 2-3 เท่า) ปริมาณ/รายการไม่ตรงความต้องการ -> ต้อง Write-off เป็นต้นทุนจริงในที่สุด
- ควรเรียกอะไหล่ที่มากับโครงการว่า Commissioning Spare Part เพื่อแก้ปัญหาที่เกิดจากการติดตั้ง/ทดลองใช้/อุบัติเหตุ (ตกหล่น น้ำ ฝุ่น ความชื้น อุณหภูมิผิดปกติ); ไม่ควรรับเข้าคลังเป็นอะไหล่บำรุงรักษา
- เป็นความรับผิดชอบของผู้ผลิต/EPC (Engineering, Procurement, Construction Contractor); บำรุงรักษาต้องตรวจสอบทุกรายการ

## การจัดการอะไหล่สำหรับงานบำรุงรักษา (Maintenance Spare Part) (book p.236)
- แบ่งตามการใช้: (1) อะไหล่ซื้อตรงไม่สำรองคลัง สำหรับงานตามแผน (2) อะไหล่สำรองคลัง สำหรับ CM-Unplanned
- **ซื้อตรง (Planned)**: ไม่เข้า Max/Min, Just in Time, ไม่นับใน Spare Part Turnover Rate; ข้อยกเว้นคืออะไหล่ใช้ร่วมหลายเครื่องที่ตารางไม่พร้อมกัน (เช่นรถ 30 คัน PM ทุก 10,000 km) ต้องรวมความต้องการงานตามแผน+นอกแผน แล้วกำหนด Max-Min/Safety Stock ด้วยสถิติ
- **สำรองคลัง (CM-Unplanned)**: ไม่ทราบเวลาเกิด; อะไหล่วิกฤติที่ Lead Time ยาว/ราคาสูง ต้องให้ผู้เกี่ยวข้องพิจารณา ใช้ Max/Min, Safety Stock ตามหลัก Risk Based Stock Recommendation ให้สอดคล้องกลยุทธ์ซ่อมบำรุง (Sustainable)

## รูปที่ 9.1 Demand/Supply Side Management (book p.237)
- ความต้องการอะไหล่เริ่มที่การเลือกงานตามแผน (RCM, บทที่ 5) -> RCM คัดกรองความวิกฤติของเครื่องจักร ซึ่งคัดกรองความสำคัญอะไหล่ไปด้วย; งานตามแผนส่งผลต่อ CM-Unplanned ซึ่งบอกปริมาณอะไหล่ที่จะใช้ = Part Demand Side Management
- แผนผังเหมือนรูป 8.1: ช่วง PM Selection + PM Optimization = Demand Side; Stock Performance (Risk Based Spare Part Optimization) = Supply Side
- ข้อมูลสำคัญสำหรับคำนวณความเสี่ยงของการไม่มีอะไหล่: ปริมาณความต้องการในช่วงเวลา, มูลค่าเสียหายจากการขาดอะไหล่ต่อหน่วยเวลา (Cost of Stock out Rate/Unit Time), Lead Time

## รูปที่ 9.2 กระบวนการ Supply Side (Risk Based Spare Part Optimization) (book p.238)
- 6 กล่อง: (1) ประเมินความวิกฤติ: เครื่องจักร, อะไหล่, ความวิกฤติรวม -> จัดกลุ่ม Fast Moving / Low / Medium / High Criticality
  (2) Fast Moving Parts: Fast Moving Method, Demand with Variance -> Max/Min, Safety Stock, Confidence Level, EOQ
  (3) Low Criticality: Fast Moving Method หรือ Average Usage Method -> Max/Min, Safety Stock, Confidence Level
  (4) Medium Criticality: Average Usage Method หรือ Demand Simulation Method -> Max/Min, Cost Ratio (Risk)
  (5) High Criticality: Demand Simulation Extended Method -> Max/Min, Cost Ratio (Risk)
  (6) Consolidation of Part Demands (รวมความต้องการ)
- สรุปวิธี: Fast moving ใช้ EOQ+variance; Low ใช้ EOQ + average rate; Medium ใช้ average rate หรือ Monte Carlo; High ใช้ Monte Carlo ที่เชื่อมแผนงานบำรุงรักษา

## อะไหล่สำรองคลัง (Stock Item) และไม่สำรองคลัง (Non-stock Items) (book p.238-239)
- Stock Item: จัดหาเก็บในคลังเพื่อพร้อมเบิกตลอดเวลา คำนวณปริมาณให้พอใช้ภายใต้ความเสี่ยงหนึ่ง
- Non-stock: ซื้อตรงเข้างาน; รู้ Lead Time และเป็นงานตามแผน
- ข้อมูลที่ต้องมีในรายการ: On Hand, Lead Time, ราคา; สำหรับ stock เพิ่ม Max, Min, EOQ, ROP, Safety Stock
- ควรแยกอะไหล่ตามประเภทการใช้งานซึ่งมีความวิกฤติเกี่ยวข้อง

## ดัชนีการบริหารอะไหล่ (Spare KPIs) (book p.239)
- Stock Turnover Rate = มูลค่าอะไหล่ที่เบิกออก / มูลค่าอะไหล่ทั้งหมดในคลัง; ต่ำ = สะสมไม่ถูกเบิก เสี่ยง Write-off
- Stock Service Rate = จำนวนรายการอะไหล่ที่เบิกได้ / จำนวนรายการที่ขอเบิกในช่วงประเมิน (ตรงความต้องการแค่ไหน)
- Stock out Rate = ปริมาณอะไหล่ที่เบิกไม่ได้ (ไม่มีของ) / ปริมาณที่ขอเบิกทั้งหมด (พอไหม)
- Stock Value / Asset Replacement Value = มูลค่าอะไหล่รวมในคลัง / มูลค่าซื้อทดแทนของทรัพย์สิน (ขนาดคลังเมื่อเทียบสินทรัพย์)
- รายละเอียดอยู่ในบทที่ 3 (Maintenance Strategic Report)

## การบริหารอะไหล่ (book p.240)
- 3 ส่วน: (1) Spare Part Information และกำจัดรายการซ้ำซ้อน (codification มาตรฐาน) (2) Supply Side (3) Demand Side
- ระบบข้อมูลอะไหล่เป็นฐานราก; ตัวชี้วัดคือมีรายการซ้ำซ้อนเพียงใด

## การบริหารอะไหล่ด้านอุปสงค์และอุปทาน (book p.240)
- รูปที่ 9.3: งานบำรุงรักษารวม แยกเป็นงานตามแผน (Scheduled PM -> งานตามแผน + CM-Planned) กับงานนอกแผน (CM-Unplanned). Demand Side ได้ "ปริมาณความต้องการตามแผน" และ "นอกแผน". Supply Side: ความต้องการตามแผน = จัดซื้อตามแผน; นอกแผน = สำรองคลัง ด้วย Max/Min/ROP/EOQ, Safety Stock, Probability to Meet Demands, Risk of Stock out, Cost Ratio

## Demand Side Management (book p.241)
- CM-Unplanned: คำนวณจำนวนครั้งที่คาดจากข้อมูลเสียในอดีต + ตัวแปรสถิติ (เช่น beta, eta Weibull) + Monte Carlo
- Planned Maintenance ลดผลกระทบจากการเสีย; ตัวแปร beta/eta ใช้เลือก PM และคาบ; เพิ่ม PM จนไม่มี CM-Unplanned เลยได้ แต่ cost รวมสูง จึงต้องหา optimum; อะไหล่สำรองคลังเพื่อสู้กับความเสี่ยงที่ยังเสียได้ไม่ว่าจะทำ PM หรือไม่
- Condition Monitoring PM ตรวจจับ Potential Failure ล่วงหน้า -> CM-Planned; ต้องสะสมอะไหล่หรือไม่ขึ้นกับ Lead Time เทียบกับเวลาที่เหลือก่อน CM-Unplanned (ถ้า Lead Time ยาวกว่า ต้องสะสม)

## Supply Side Management (book p.241-242)
- กระบวนการ 5 ข้อ: (1) คัดกรองตาม Turnover ด้วย ABC Analysis (2) จัดอะไหล่ตาม Part Criticality (3) ตารางความสัมพันธ์ความวิกฤติอะไหล่-เครื่องจักร (4) ความเสี่ยงและการบริหารความเสี่ยง (5) คำนวณระดับสะสม: EOQ; ค่าเฉลี่ย + Safety Stock; Simulation

## ABC Analysis ตาม Turnover (book p.242-243)
- Turnover = Qty x Unit Price (มูลค่าเบิกใช้)
  | กลุ่ม | ความหมาย | สัดส่วนมูลค่า turnover |
  |---|---|---|
  | A | หมุนเวียนช้า (very slow) | ราย การ ที่มูลค่าหมุนสูงสุด 80% ของ total |
  | B | หมุนเวียนปานกลาง | 15% ถัดไป |
  | C | หมุนเวียนเร็ว (fast moving) | 5% สุดท้าย (หลายรายการ มูลค่าต่ำ) |
  - รูปที่ 9.4: Pareto curve สะสมถึง 80% / 95% / 100% แบ่ง A/B/C. ตามที่ภาพ: A (Very Slow) เป็นกลุ่มแรกของแกน X; ตัวหนังสือเรียก A = หมุนเวียนช้า แม้สัดส่วน 80% (น่าจะหมายถึงมูลค่า (Qty x Price) ช่วงต้นของเส้นโค้ง) [สับสนเล็กน้อยในต้นฉบับ: ข้อความหน้า 242 บอกว่า A มีมูลค่าหมุนสูง 80% แต่ภาพ label A = Very Slow]
- ไม่ได้คำนึงถึงความวิกฤติ; ข้อควรระวัง: Turnover มี 2 ตัวแปร (qty, price) รายการหมุนสูงราคาต่ำหรือหมุนต่ำราคาสูงอาจอยู่ผิดกลุ่ม
- ควรคิด turnover แยกอะไหล่ที่ซื้อตรง (PM) ออกจากอะไหล่สำรองคลัง ไม่ควรรวมกัน (มิฉะนั้นสับสน และ On Hand สูงกว่า Max)

## Part Criticality (book p.243)
- เกณฑ์หลัก 3 ข้อ: ราคา (Price), Lead Time, ความสามารถตรวจวัดอาการเสีย (Condition Monitoring / Failure Detect-ability)
- เป็นความสำคัญของตัวอะไหล่เอง ไม่คำนึงว่าใช้ที่ไหน
- ความวิกฤติเครื่องจักร 3 กลุ่ม:
  | กลุ่ม | ความวิกฤติ | ผลเมื่อเสีย |
  |---|---|---|
  | A | สูงมาก | กระบวนการผลิตหยุด ความเสียหายสูง |
  | B | ปานกลาง | เสียหายปานกลาง |
  | C | ต่ำ | เสียหายต่ำ |

## ความสัมพันธ์ระหว่างอะไหล่กับเครื่องจักร (book p.244)
- รูปที่ 9.5 (Venn 3 วง: High / Medium / Low Criticality): Equipment Criticality ประกอบด้วย Commercial, Safety, Environment Criticality; Part Criticality ประกอบด้วย Price, Lead Time, Failure Detect-ability
- อะไหล่ X, Y, Z = ใช้เฉพาะเครื่อง High/Medium/Low (specific usage) -> แยกบริหารงานตามแผน (JIT) กับนอกแผน (ตามความเสี่ยง)
- อะไหล่ P, Q, R, W = ใช้ร่วม (common usage) P,Q,R ใช้ร่วมสองระดับ, W ใช้ทุกระดับ -> ตั้ง Max/Min, Safety Stock รวมงานตามแผน+นอกแผนได้ แต่ต้องตอบสนองเครื่องวิกฤติเป็นอย่างน้อย
- กฎ: อะไหล่ใช้ร่วมเครื่องวิกฤติต่างกัน -> criticality อะไหล่ = criticality เครื่องจักรที่สูงสุด; ที่ระดับเครื่องเท่ากัน ใช้ criticality ของตัวอะไหล่เปรียบเทียบกัน

## ตารางความสัมพันธ์ criticality อะไหล่-เครื่องจักร (book p.245-246)
- รูปที่ 9.6: ตารางรายการอะไหล่ (ตัวอย่าง bearing, battery, anvil ฯลฯ) คอลัมน์: Code, Description, EQ Criticality (A, B, C = จำนวนชิ้นที่ใช้ในเครื่องวิกฤติระดับ A/B/C สร้างจาก BOM), Part Criticality (COST, LT, CBM), On hand, Unit cost, Max, Min [ตัวเลขรายแถวอ่านไม่ออก]
- คะแนน Part Criticality: Cost, LT, CBM ให้ 1 = สูงสุด, 2 = กลาง, 3 = ต่ำ; CBM คะแนนต่ำ = ตรวจอาการล่วงหน้าไม่ได้ (เสียโดยไม่มีสัญญาณ)
- ใช้ sort ได้ตามต้องการ (เช่น ราคา -> LT -> CBM) หรือเรียงเริ่มที่ Equipment Criticality A
- การอ่านตาราง: คอลัมน์ A/B/C != 0 = ใช้ในเครื่องวิกฤตินั้น; Cost = อะไหล่แพงที่ต้องหาแหล่งซื้อถูก; LT = ต้องเร่งกระบวนการจัดซื้อ; CBM = ตรวจว่ามีงาน Condition Monitoring PM ครบหรือยัง; คอลัมน์อื่นเช่น เครื่องสำคัญมีอะไหล่สำรองแล้วหรือยัง
- ตารางนี้เป็นขั้นตอนพื้นฐานที่ต้องทำก่อนวิเคราะห์ระดับอะไหล่

## ความเสี่ยงและการบริหารความเสี่ยง (book p.246-251)
- เพิ่มระดับสะสม -> ลดความเสี่ยง แต่เพิ่ม fixed cost; มีเครื่องมือเชิงวิทยาศาสตร์ 2 แบบ: Confidence to Meet Demand และ Cost Ratio
- **Confidence Level**: % ความมั่นใจว่าในช่วง Lead Time ที่เบิกแต่ละครั้งจะมีอะไหล่ใช้ ใช้คำนวณระดับสต็อกภายใต้ความแปรปรวนของ demand และ Lead Time
- **Cost Ratio** = Expected Cost of Stock out / Expected Cost of Stock (ค่าใช้จ่ายคาดหวังจากการไม่มีอะไหล่ ÷ ค่าใช้จ่ายคาดหวังจากการมีอะไหล่สะสม) = ความเสี่ยง (Risk)

### Lead Time (book p.247)
- นับจากออก Purchase Requisition (PR) จนอะไหล่พร้อมในคลัง: กำหนด Specification -> สืบราคา/ประมูล -> พิจารณาข้อเสนอ -> ออก PO -> รับของเข้าคลัง
- ลด Lead Time ลง 20% ลดสต็อกเฉลี่ยลงเหลือครึ่งหนึ่งได้ (ตามข้อมูลที่อ้าง)
- ควรบริหาร Lead Time เชิงบวก (ให้รางวัลผู้ขายที่ส่งตรง/เร็ว เช่น ลดเวลาจ่ายเงิน); เชิงลบ (ปรับเข้มงวด) ทำให้ผู้ขายยืด Lead Time ในครั้งต่อไป วงจรอุบาทว์นำไปสู่การซื้อครั้งละมาก ๆ สต็อกสูงเกิน

### ROP / Min และ Safety Stock (book p.247-248)
- กรณี Lead Time และ Demand Rate คงที่: ROP (Min) = Demand Rate x Lead Time (รูปที่ 9.7 กราฟฟันปลา, L = Lead Time)
- ในความจริง demand แปรปรวน + Lead Time แปรปรวน -> ต้องมี **Safety Stock (SS)** = สต็อกสำรองรับความผิดปกติของทั้ง demand และ supply; กำหนดด้วยสถิติที่ Confidence Level ที่ต้องการ ในช่วงรอส่งมอบหลังเริ่มสั่งซื้อที่จุด ROP

### ความแปรปรวนและตาราง Z (book p.248-249)
- ใช้ Normal Distribution (พารามิเตอร์ mu = mean, sigma = standard deviation); Z = จำนวนเท่าของ sigma ที่ให้ความมั่นใจที่กำหนด
- รูปที่ 9.8 (ตาราง Confidence -> Z, one-sided):

  |---|---|
  | 0.841 | 1.0000 |
  | 0.850 | 1.0364 |
  | 0.875 | 1.1503 |
  | 0.900 | 1.2816 |
  | 0.925 | 1.4395 |
  | 0.950 | 1.6446 |
  | 0.975 | 1.9600 |
  | 0.995 | 2.5758 |
  | 0.9975 | 2.8070 |
- Risk of Stock out = 1 - Confidence ที่จะมีอะไหล่ใช้

### การคำนวณความเสี่ยงด้วย Cost Ratio (book p.249-251)
- Cost Ratio = Cost of Stock out / Cost of Stock
- รูปที่ 9.9: แกน X = ค่าสูญเสียจากการไม่มีอะไหล่ต่อครั้ง (x10^5 บาท), แกน Y = Cost Ratio. โซน: "Mandatory Stock Zone" (Cost Ratio สูง, ~> 9), "Risk Based Optimum Zone" (กลาง; ใช้ policy), "No Stock Zone" (ratio <= 1), และ "Insurance Stock Zone" (ค่าสูญเสียต่อครั้งสูงมาก, ขวาของ ~1.1 ล้านบาท แม้ ratio < 1)
- ตัวอย่างจุด C: Max/Min = 3/2, stock out cost 600,000 บาท/ครั้ง, expected cost of stock = 98,360.65 บาท -> Cost Ratio = 600,000 / 98,360.65 = 6.1
- ลดสต็อก -> Cost Ratio สูงขึ้น (โอกาสขาดเพิ่ม); เพิ่มสต็อก (เช่น 4/3 ...) -> ratio ลดเข้าหา 1.0; ที่ ratio = 1 ค่าขาด = ค่าเก็บ ไม่คุ้มสะสมเพิ่ม; ต่ำกว่า 1 = เหลือค้างมาก
- ถ้า ratio < 1 ไม่ควรเก็บ ยกเว้นค่าสูญเสียต่อครั้งสูงมากจนบริษัทรับไม่ได้ -> Insurance Part

### วิธีบริหารความเสี่ยง (book p.251-252)
- ฝ่ายบริหารกำหนด policy ใช้ Cost Ratio เป็นกรอบ อำนาจอนุมัติ 3 ระดับ:
  | โซน | ผู้ปฏิบัติ |
  |---|---|
  | Mandatory Stock Zone (Cost Ratio สูง) | สะสมได้เลยไม่ต้องขออนุมัติ |
  | Stock with Approval Zone | สะสมโดยอนุมัติตามระดับบริหารที่กำหนดใน policy |
  | No Stock Zone (stock cost >= stock out cost) | ไม่ควรสะสม |
  | Insurance Part (ค่าขาดต่อครั้งเกินเกณฑ์ เช่น 1,100,000 บาท แม้ ratio < 1) | สะสมได้โดยขออนุมัติระดับบริหาร |
- Implementation: (1) นโยบายความเสี่ยง มอบหมายอำนาจกำหนดระดับอะไหล่ (2) เครื่องมือคำนวณความเสี่ยงเชิงสถิติจากข้อมูลจริง (3) กระบวนการอนุมัติ (4) กระบวนการจัดหา/เติมตามระดับที่กำหนด [(2)-(4) ติดป้าย ISO ในต้นฉบับ -- ไม่ได้อธิบาย]

## การคำนวณระดับอะไหล่ด้วย EOQ (book p.252-253)
- EOQ = ปริมาณสั่งซื้อต่อครั้งที่ประหยัดสุด เมื่อ Lead Time และ Demand Rate คงที่. รูปที่ 9.10: สต็อกเฉลี่ย = Q/2
- Ch = ค่าเก็บต่อหน่วย; Cp = ค่าจัดซื้อต่อครั้ง; A = ปริมาณใช้ต่อปี
  - ค่าเก็บรวม = (Q/2) x Ch
  - ค่าจัดซื้อรวม = (A/Q) x Cp  (หนังสือพิมพ์เป็น Q/2 x Cp ในหน้า 253 แต่ Cost_total ใช้ A/Q)
  - Cost_total = (Q/2)*Ch + (A/Q)*Cp
  - ต่ำสุดเมื่อค่าเก็บ = ค่าจัดซื้อ: **Q = sqrt(2 x A x Cp / Ch)**

## อะไหล่ภายใต้ความแปรปรวนของ Lead Time และ Demand Rate (book p.253-255)
- รูปที่ 9.11: กราฟสต็อกลดแบบไม่สม่ำเสมอ; ROP อาจไม่พอเมื่อ demand สูงผิดปกติใน Lead Time; ใช้ข้อมูลเบิกจริง (ปริมาณ/จำนวนครั้ง) หา distribution ของ demand และข้อมูลส่งมอบหา distribution ของ Lead Time
- รูปที่ 9.12: SS สำหรับกรณี Lead Time คงที่ + demand แปรปรวน และกรณี demand คงที่ + LT แปรปรวน; ทั้งสองเป็น Normal; ตัวอย่าง 90% -> Z = 1.2816
- รูปที่ 9.13 สูตร:
  - ROP = D_avg x LT_avg + SS
  - SS = z x sigma_combined
  - **sigma_combined = sqrt( (sigma_D)^2 x LT_avg + (sigma_LT x D_avg)^2 )**
  - D_avg = demand เฉลี่ย, LT_avg = lead time เฉลี่ย, sigma_D = SD ของ demand rate, sigma_LT = SD ของ lead time
- **ตัวอย่าง (book p.255-256)**: demand เฉลี่ย 12 ชิ้น/ปี (= 12/365 ต่อวัน), Lead Time เฉลี่ย 90 วัน, sigma_D = 0.14 ชิ้น/วัน, sigma_LT = 26.5 วัน, confidence 90% (Z = 1.2816)
  - SS = 1.2816 x sqrt( 0.14^2 x 90 + (26.5 x 12/365)^2 ) = 2.035 ~ 2 ชิ้น
  - ROP = (12/365) x 90 + 2 = 2.95 + 2 ~ 5 ชิ้น  (ใช้เป็น Min)

  - Part Supply Side Optimization: ประเมินความวิกฤติอะไหล่ -> คำนวณระดับสะสม (ตามหลักการเลือกวิธีคำนวณ) -> ต้องการปรับด้านอุปสงค์? (ใช่ = ไปปรับด้านอุปสงค์) -> ต้องการรวมยอด? -> รวมยอดอะไหล่สะสม -> วิเคราะห์ผลการคำนวณและขออนุมัติ (ตามนโยบายบริหารความเสี่ยง) -> อนุมัติ? (ไม่ = ไม่ต้องสะสม; ใช่ = สะสมตามผลการคำนวณ, บริหารอะไหล่และจัดหา)
  - ความต้องการอะไหล่สำหรับงานนอกแผน และผลการปรับด้านอุปสงค์จากงานตามแผน ป้อนเข้า Supply Side
- รูปที่ 9.23 (Part Supply Side Reduction, ใช้ข้อมูลจากระบบ ERP): Part/Equipment Criticality Review -> Select Part Recommendation Method -> Calculate Recommendation & Analysis (ทบทวนใหม่เมื่อ criticality เปลี่ยน) -> Demand Side Adjustment Needed? -> Need Consolidation? -> Result Analysis -> Approve? -> Upload (ปรับข้อมูลให้จัดซื้อ/คลังทราบ)
- รูปที่ 9.24 (Demand Side Reduction / Advanced Part Demand Side Management): RCM คัดเลือกและกำหนดคาบ PM: Equipment Criticality Review -> Select Failure Mode -> Maintenance Analysis @ Selected Failure Mode (บทที่ 5 RCM, บทที่ 6 Failure data Analysis, บทที่ 8 [ตามที่หนังสืออ้าง] Scheduled PM Task and Interval Selection and Optimization) -> Task Grouping (รวมงานที่มีคาบใกล้กัน/เครื่องกลุ่มเดียวกัน) -> อนุมัติ -> Upload เข้า CMMS/ERP; ผลส่งไปปรับระดับอะไหล่สะสมและแผนจัดหาอะไหล่

## สรุปท้ายบท (book p.271)
- ค่าใช้จ่ายอะไหล่มีทั้งตรง (ค่าอะไหล่ที่เบิก, ค่าถือครอง) และทางอ้อม (หยุดผลิตรออะไหล่)
- Demand Side = คาดการณ์ความต้องการให้ถูก; Supply Side = จัดหาให้ทันตาม Max/Min และความเสี่ยงที่รับได้ ซึ่งกำหนดโดยฝ่ายบริหาร; หนีไม่พ้นวิชาสถิติ
- Accountability: ต้องอธิบายได้ว่าทำไมสั่ง/เก็บเท่านั้น; ความรับผิดชอบร่วมกันของบำรุงรักษา คลัง ฝ่ายบริหาร; ฝ่ายบริหารต้องชี้ขาดว่ากลุ่มอะไหล่ไหนใครรับผิดชอบกำหนดระดับสะสม; ใช้เครื่องมือคำนวณที่ถูกต้อง (คำนวณมืออาจไม่มีประสิทธิภาพ); ระบบต้องเชื่อม Maintenance Adjustment กับ Stock Recommendation Adjustment
- ฝ่ายบริหารต้องกำหนด/เห็นชอบกระบวนการ: การจัดทำรหัสอะไหล่ การเสนอและอนุมัติระดับสะสม ติดตามผ่าน Maintenance Strategic Report (บทที่ 3)

## Links to compressor failure hierarchy / OREDA / ISO 14224
- Spare demand = f(failure mode, beta, eta) ต่อ equipment; Spare Part DSx Model (p.263) ใช้ Equipment, Failure Mode, Beta, Eta, ประเภทงานที่เรียกใช้อะไหล่, Stock out cost rate => ต้องมี failure mode ที่ระดับ item/component (ตรงกับ ISO 14224 failure mode + maintainable item) และ failure rate (OREDA ให้ค่า MTBF/failure rate ใช้กับ Basic Average Method p.257 แต่หนังสือเตือนว่าสมมติ constant rate)
- Equipment Criticality (Commercial, Safety, Environment) p.244 สอดคล้องกับการจัด criticality / FMECA severity; Part Criticality (Price, Lead Time, Detectability/CBM) คล้าย detectability ใน FMECA/RPN และ ISO 14224 detection method
- ตาราง Equipment-Part criticality จาก BOM (p.245-246) = แนวทางผูก spare กับ equipment taxonomy / CMMS item hierarchy; ต้องมี spare codification มาตรฐานและกำจัดรายการซ้ำ (p.240) เพื่อเชื่อม spare กับ failure hierarchy ใน CMMS
- งาน Demand Side Reduction ใช้ RCM + Failure Data Analysis + Equipment Catalog Profile (p.269-270) = ลำดับ RCM -> PM task/interval -> spare
- Condition Monitoring / Lead Time: ถ้า P-F interval < Lead Time ต้องสต็อกอะไหล่ (p.241)
- Hidden failure, redundancy (บทที่ 8) ส่งผลต่อ spare ของเครื่องสำรอง (compressor standby) - ต้องวิเคราะห์ความเสี่ยงทั้งระบบ
- ไม่มี failure mode/mechanism list หรือ code ตาม ISO 14224/OREDA ในบทที่ 8-9 (มีเพียงการอ้างถึง Failure Mode แบบทั่วไปและ failure pattern B/C/D)
